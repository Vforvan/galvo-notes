# ⏱️ 时序规范与参数表

> [!info] 一句话版本
> 时钟 2 MHz（周期 500 ns），数据必须在采样沿**之前 50 ns** 就稳定、**之后 100 ns** 才允许变化。
> 这两个数字（tDS、tDH）是**厂商给出的唯一硬性时序指标**，极其宽松，很好满足。

---

## 1. 基础时间参数

| 参数 | 符号 | 值 | 单位 | 来源 |
|---|---|---|---|---|
| 时钟频率 | f_CLK | **2** | MHz | ✅ 规范 |
| 时钟周期 | T_CLK | **500** | ns | = 1 / 2 MHz |
| 帧长度 | T_FRAME | **10** | μs | ✅ 规范 = 20 × 500 ns |
| 帧率 | f_FRAME | **100** | kHz | ✅ 规范 |
| 每帧位数 | N | **20** | bit | ✅ 规范 |
| 比特率 | — | **2** | Mbit/s | ✅ 规范 |
| **数据建立时间** | **tDS** | **≥ 50** | ns | ✅ 规范 |
| **数据保持时间** | **tDH** | **≥ 100** | ns | ✅ 规范 |

> [!quote] 规范原文（唯一的时序表）
> ```text
> Clock to data timing
> Description        Name    Min    Typ    Max    Units
> data-in setup time tDS     50                       ns
> data-in hold time  tDH            100               ns
> ```
> — `Documents_TD_XY2-100_R0703.pdf` 第 2 页
> — `Raylase_Interface_XY2-100.pdf` 第 1 页（同一张表）

> [!warning] ⚠️ 关于 tDH 的表格排版
> 两份 PDF 里 tDH 的 "100" 印在 **Typ**（典型值）列，tDS 的 "50" 印在 **Min** 列。
> 这很可能是排版问题（正常应两个都是 Min）。
> **工程上按"最小 100 ns"处理是最安全的**——反正这个要求极其宽松，轻松满足。

## 2. 这些参数怎么理解

### 关键：相对哪个沿？

规范定义了数据"变化沿"和"采样沿"，但**没有明说 tDS/tDH 是相对哪个沿**。
根据"下降沿采样"这一事实，工程上一致的理解是：

```text
                         ┌───────────────────────────┐
CLK                      │                           │
              ───────────┘                           └───────────
                         ↑                           ↑
                    上升沿：                       下降沿：
                  数据在此变化                  振镜在此采样
                 （"Clock to data"的起点）
                         
DATA       ──────────XXXXX═══════════════════════XXXXX──────────
                         │  ← 新数据建立 →  │
                         
                         │←───── 数据必须已稳定 ─────→│
                         
              tDS 是数据相对「采样沿(下降沿)」提前稳定的时间
              tDH 是数据相对「采样沿(下降沿)」之后保持的时间
```

**通俗说法**：
> 振镜在**时钟下降沿**那一瞬间"拍照"。
> 拍照前 50 ns 数据就得摆好姿势，拍照后 100 ns 内不许动。

### 时间预算非常充裕

```text
一个时钟周期 = 500 ns
├─ 高电平 ≈ 250 ns  ← 数据在这段时间内变化并稳定
└─ 低电平 ≈ 250 ns  ← 振镜在起始处采样

需要满足：tDS = 50 ns（占周期 10%）
          tDH = 100 ns（占周期 20%）
```

> [!tip] 💡 结论：时序余量巨大
> 500 ns 的周期里，只需要 50 ns + 100 ns = 150 ns 的约束。
> 只要你不是故意把数据拖到下降沿之后才改变，**基本不可能违反**。
>
> 这也解释了为什么连 Arduino Nano（16 MHz，软件翻转 GPIO）都能驱动振镜——
> 虽然达不到精确 2 MHz，但时序关系对得上就能工作。

## 3. 完整的时序波形（标注所有参数）

```text
                    T_CLK = 500 ns
              ├───────────────────────┤
              ┌───────────────────────┐
CLK           │                       │
     ─────────┘                       └───────────────────────
              ↑                       ↑
         上升沿(变化)             下降沿(采样)
         
              │                       │
DATA  ────────┼─────═══════════════════┼──────────────────────
              │     ↑                 │
              │  数据在此时段内完成变化  │
              │                       │
              │        稳定            │
              
              tDS ≥ 50 ns 是相对采样沿(↓)的提前量
              tDH ≥ 100 ns 是相对采样沿(↓)的滞后量

                                     
              ├── 整帧 10 μs = 20 个 500 ns ──┤
```

## 4. SYNC 相关时序

| 参数 | 值 | 说明 |
|---|---|---|
| SYNC 上升沿 | 帧开始 | 与第 1 位（C2）对齐 |
| SYNC 高电平持续 | **19 bit** = 9.5 μs | ✅ 规范 |
| SYNC 下降沿 | 第 20 位（校验位）开始 | 帧尾预告 |
| SYNC 低电平持续 | **1 bit** = 500 ns | |
| SYNC 与 CLK 相位关系 | ⚠️ 规范未明确规定 | 见下文 |

> [!important] SYNC 与 CLK 的相位关系：规范没有明确
> 规范只说"SYNC 变高时第 1 位可以发送"，**没有画 CLK 与 SYNC 的边沿对齐关系**。
> 
> 💡 主流实现的做法（两种都有）：
> - **方案 A**：SYNC 在第 1 位对应的**时钟上升沿**同时变高
> - **方案 B**：SYNC 在帧开始前**提前一点**变高
>
> **建议**：参考你手上振镜的说明书，或用逻辑分析仪抓一台能工作的设备 🔬。
> 详见 [[03-调试与排错篇/02-逻辑分析仪抓包]]。

## 5. 各厂商实现的时钟差异

> [!warning] ⚠️ 重要：不是所有"XY2-100"都跑 2 MHz
> 规范规定 2 MHz，但实测中有厂商偏离。参考开源实现的观察：

| 实现 | 时钟 | 说明 |
|---|---|---|
| 规范 | **2 MHz** | ✅ 标准 |
| Arduino Nano 版 | 低于 2 MHz | 作者原话："Does this work at the standard rate of 2MHz? Most likely not, but an Arduino Nano seems to be able to drive a galvo just fine." |
| RP2040 PIO 版 | 可精确 2 MHz+ | 用 PIO 外设精确生成 |
| i.MX RT FlexIO | 可精确控制 | NXP 官方方案 |
| FPGA | 精确 2 MHz | 分频产生 |

> [!note] 为什么低于 2 MHz 也能工作
> 因为振镜内部有**自己的时钟恢复/采样逻辑**，只要：
> 1. 时钟不太快（不超过它能接收的上限）
> 2. 时序关系正确（沿的关系对）
> 3. 帧结构正确
>
> 就能工作，只是**更新率下降**（帧变长 → 每秒帧数变少）。
>
> ⚠️ **但这不代表你可以随意降频**。降频会：
> - 降低更新率 → 影响加工速度
> - 可能超出振镜内部 PLL 的锁定范围 → 直接不工作
>
> **正确定位**：2 MHz 是规范值，偏离是"能凑合"，不是"推荐"。

## 6. 帧率与实际的换算

| 时钟频率 | 帧长 | 帧率 | 备注 |
|---|---|---|---|
| 2 MHz | 10 μs | **100 kHz** | ✅ XY2-100 标准 |
| 4 MHz | 5 μs | 200 kHz | = XY2-200 |
| 1 MHz | 20 μs | 50 kHz | 降频运行 |
| 500 kHz | 40 μs | 25 kHz | 严重降频 |

> [!tip] 💡 记住这个换算
> ```text
> 帧率 = 时钟频率 ÷ 20
> ```
> 2 MHz ÷ 20 = 100 kHz ✅
> 这是本协议最核心的一个公式。

## 7. 时序设计检查清单

写代码/画 FPGA 时逐条确认：

- [ ] 时钟频率是否正确（2 MHz）？
- [ ] 时钟是否**连续运行**（不停顿）？
- [ ] 数据是否在时钟**上升沿**变化？
- [ ] 数据是否在时钟**下降沿前 50 ns** 就稳定？
- [ ] 数据是否在采样沿后保持 **100 ns**？
- [ ] SYNC 是否在帧开始（第 1 位）时拉高？
- [ ] SYNC 是否在第 **19** 位之后（第 20 位前）拉低？
- [ ] X / Y 是否**同一帧内同时发送**？
- [ ] 帧与帧之间是否**没有间隙**？
- [ ] 位置不变时是否仍然**持续发送**？

## 8. 常见时序错误对照

| 错误 | 现象 | 修正 |
|---|---|---|
| SYNC 高电平覆盖 20 位 | 帧边界识别错误，可能完全不工作 | 改为 19 位 |
| SYNC 只在帧头发一个短脉冲 | 振镜不认帧 | 改为持续 19 位长的电平 |
| 数据在下降沿变化 | 建立时间不足，数据不稳定 | 改为上升沿变化 |
| 时钟停停走走 | 振镜内部环路失锁 | 改为连续运行 |
| 帧之间有长间隔 | 振镜"以为"要回零或保持异常 | 改为背靠背连续 |
| X/Y 不同步发送 | 未发送的轴跑到 0 或满量程 | 同一帧内同时发 |
