# 🔢 位置数据编码

> [!info] 一句话版本
> 位置用 **16 位偏移二进制**表示：`0x0000` = 最负端，`0x8000` = **中心（零位）**，`0xFFFF` = 最正端。
> 换算公式：**发送值 = 目标值 + 32768**。

---

## 1. 编码方式：偏移二进制

### 什么是偏移二进制

普通无符号数只能表示 0 ~ 65535，但振镜位置需要表示**正负**（中心两侧）。
解决办法：**把有符号数整体"搬"到无符号区间**，加上一个偏移量 32768。

```text
有符号值域              +32768 偏移             无符号发送值
                                   
  +32767  ──────────────────────────────→  0xFFFF  (65535)
     ⋮                                             ⋮
      +1  ──────────────────────────────→  0x8001  (32769)
       0  ──────────────────────────────→  0x8000  (32768)  ★ 中心
      −1  ──────────────────────────────→  0x7FFF  (32767)
     ⋮                                             ⋮
  −32768  ──────────────────────────────→  0x0000  (0)
```

> [!important] 核心公式
> ```text
> 发送值 = 目标值 + 32768        （目标值 ∈ [−32768, +32767]）
> 目标值 = 发送值 − 32768        （发送值 ∈ [0, 65535]）
> ```
> **中心位置是 `0x8000`，不是 `0x0000`！** 这是新手最容易搞错的点。

> [!quote] 规范原文
> "The next 16 bits are data information (D15-D0, **offset binary**)"
> — `Documents_TD_XY2-100_R0703.pdf` 第 2 页
> — `Raylase_Interface_XY2-100.pdf` 第 1 页

### 偏移二进制 vs 补码

| 数值 | 偏移二进制 | 补码（Two's Complement） |
|---|---|---|
| −32768 | `1000 0000 0000 0000` (0x8000) | `1000 0000 0000 0000` (0x8000) |
| −1 | `0111 1111 1111 1111` (0x7FFF) | `1111 1111 1111 1111` (0xFFFF) |
| **0** | **`1000 0000 0000 0000` (0x8000)** | **`0000 0000 0000 0000` (0x0000)** |
| +1 | `1000 0000 0000 0001` (0x8001) | `0000 0000 0000 0001` (0x0001) |
| +32767 | `1111 1111 1111 1111` (0xFFFF) | `0111 1111 1111 1111` (0x7FFF) |

> [!tip] 💡 转换捷径
> **偏移二进制 = 补码的最高位取反**（其他位不变）。
> ```c
> uint16_t offset_binary = (uint16_t)(twos_complement ^ 0x8000);
> ```
> 或者更直接：`offset_binary = (uint16_t)(signed_value + 32768);`

> [!note] sigrok 解码器的处理
> 解码器内部按 MSB-first 拼出 16 位无符号值，然后：
> ```python
> pos = pos if pos < 32768 else pos - 65536
> ```
> 即把无符号值转成**有符号值**（−32768 ~ +32767）输出。
> 这就是为什么你在 PulseView 里看到的位置值是**负数到正数**，而不是 0~65535。

## 2. 完整换算链

从"物理角度"到"线上比特"，中间要经过 4 步：

```mermaid
flowchart LR
    A["物理角度<br/>θ（光学角）"] -->|"÷ 满量程 × 65536"| B["归一化值<br/>0 ~ 65535"]
    B -->|"+ 偏移已在其中"| C["16 位编码<br/>0x0000 ~ 0xFFFF"]
    C -->|"取 16 位"| D["比特流<br/>D15…D0"]
    D -->|"加控制字和校验"| E["20 位帧"]
    
    style A fill:#ffe4e1
    style C fill:#e1f0ff
    style E fill:#e8f5e9
```

### 步骤 1：角度 → 归一化

```text
归一化值 = (θ − θ_min) / (θ_max − θ_min) × 65535
```

其中 θ 是**光束偏转角（光学角）**。

### 步骤 2：归一化 → （如果从有符号值出发）

```text
有符号值 = 归一化值 − 32768        （范围 −32768 ~ +32767）
发送值   = 有符号值 + 32768 = 归一化值
```

> [!tip] 💡 实际简化
> 如果你直接从"角度"算到"发送值"，其实一步就够：
> ```text
> 发送值 = round( (θ − θ_min) / (θ_max − θ_min) × 65535 )
> ```
> "偏移"这一步在把角度映射到 0~65535 时**自动完成了**。

### 步骤 3：发送值 → 比特

```text
D15 = (发送值 >> 15) & 1     ← 先发
D14 = (发送值 >> 14) & 1
  ⋮
D00 = (发送值 >>  0) & 1     ← 后发
```

## 3. 角度 ↔ 编码 换算表

假设满量程 ±20°（光学角），则：

| 光学角 θ | 归一化比例 | 发送值（hex） | 发送值（dec） | 有符号解释 |
|---|---|---|---|---|
| −20.000° | 0.000 | `0x0000` | 0 | −32768 |
| −15.000° | 0.125 | `0x2000` | 8192 | −24576 |
| −10.000° | 0.250 | `0x4000` | 16384 | −16384 |
| −5.000° | 0.375 | `0x6000` | 24576 | −8192 |
| **0.000°** | **0.500** | **`0x8000`** | **32768** | **0** |
| +5.000° | 0.625 | `0xA000` | 40960 | +8192 |
| +10.000° | 0.750 | `0xC000` | 49152 | +16384 |
| +15.000° | 0.875 | `0xE000` | 57344 | +24576 |
| +20.000° | 1.000 | `0xFFFF` | 65535 | +32767 |

> [!warning] ⚠️ 这张表的前提
> 表里的角度值是**假设满量程为 ±20° 光学角**。
> **你的振镜实际满量程必须查它自己的手册！** 不同型号差别很大（±7°、±10°、±20°、±25° 都有）。
>
> ⚠️ 另外注意：**振镜内部的"满量程"通常指它自己的 DAC 满量程，不一定等于机械极限或光学极限。**
> 具体映射关系一般由振镜厂商的标定决定，你在协议层只管发满量程的 0~65535。

## 4. 分辨率计算

### 1 LSB 对应多少角度

```text
角度分辨率 = (θ_max − θ_min) / 65536
```

| 满量程（光学角） | 1 LSB 角度 | 换算成 mrad |
|---|---|---|
| ±5°（共 10°） | 0.000153° | 2.7 μrad |
| ±10°（共 20°） | 0.000305° | 5.3 μrad |
| ±20°（共 40°） | 0.000610° | 10.7 μrad |
| ±25°（共 50°） | 0.000763° | 13.3 μrad |

> [!tip] 💡 快速记忆
> **±20° 光学角时，1 LSB ≈ 0.61 mrad ≈ 10.7 μrad**（约 0.0006°）。

### 1 LSB 对应多少平面位移

结合场镜焦距 f：

```text
平面分辨率 = f × 角度分辨率（弧度）
```

例：场镜 f = 160 mm，满量程 ±20°：

```text
角度分辨率 = 40° / 65536 = 6.1e-4 ° = 1.065e-5 rad
平面分辨率 = 160 mm × 1.065e-5 = 1.70 μm
```

> [!note] 有意思的对比
> 16 位分辨率给出约 **1.7 μm** 的理论平面分辨率。
> 但实际激光光斑本身就有 **20~50 μm** 直径。
> 所以**分辨率远优于实际需要**——真正限制精度的是振镜的线性度、温漂和场镜畸变，而不是位数。
>
> 这解释了为什么很多场景 16 位足够，也解释了为什么"16 位分辨率 ≠ 16 位精度"（见 [[00-入门篇/04-常见误区]] 误区 4）。

## 5. 代码实现

### C：有符号值 → 16 位发送值

```c
#include <stdint.h>

/* 输入: -32768 .. +32767 的目标值
 * 输出: 0x0000 .. 0xFFFF 的发送值 */
static inline uint16_t xy2_encode(int16_t target)
{
    /* 加偏移，等价于最高位取反 */
    return (uint16_t)((int32_t)target + 32768);
}

/* 反向: 发送值 -> 有符号值 */
static inline int16_t xy2_decode(uint16_t wire)
{
    return (int16_t)((int32_t)wire - 32768);
}
```

> [!warning] ⚠️ C 语言的坑
> 不要写 `return target + 32768;`（int16_t 会溢出）。
> 一定要先提升到 int32_t 再转 uint16_t，如上所示。

### C：角度 → 发送值

```c
/* 把光学角(度)映射到 16 位发送值
 * angle_max_deg: 满量程正端角度，例如 20.0 */
uint16_t angle_to_wire(double angle_deg, double angle_max_deg)
{
    double norm = (angle_deg + angle_max_deg) / (2.0 * angle_max_deg); /* 0..1 */
    if (norm < 0.0) norm = 0.0;
    if (norm > 1.0) norm = 1.0;
    return (uint16_t)(norm * 65535.0 + 0.5);   /* 四舍五入 */
}
```

### Python：验证用

```python
def encode(target: int) -> int:
    """-32768..32767 -> 0..65535"""
    assert -32768 <= target <= 32767
    return target + 32768

def bits(value16: int) -> str:
    """转成 16 位 MSB-first 字符串"""
    return format(value16 & 0xFFFF, '016b')

def one(target: int) -> str:
    """生成单轴的 20 位比特串（含控制字和偶校验）"""
    b = bits(encode(target))
    p = b.count('1') % 2              # 偶校验: 数据中 1 的个数为偶数时 p=0
    return '001' + b + str(p)

def frame(target_x: int, target_y: int) -> tuple[str, str]:
    """生成 X/Y 两条线的比特串（同一帧内同步发送）"""
    return one(target_x), one(target_y)

for t in (-32768, -1, 0, 1, 32767):
    v = encode(t)
    b = bits(v)
    p = b.count('1') % 2
    print(f"target={t:7d}  wire=0x{v:04X}  bits={b}  parity={p}  frame=001{b}{p}")
```

**运行结果**：

```text
target= -32768  wire=0x0000  bits=0000000000000000  parity=0  frame=00100000000000000000
target=     -1  wire=0x7FFF  bits=0111111111111111  parity=1  frame=00101111111111111111
target=      0  wire=0x8000  bits=1000000000000000  parity=1  frame=00110000000000000001
target=      1  wire=0x8001  bits=1000000000000001  parity=0  frame=00110000000000000010
target=  32767  wire=0xFFFF  bits=1111111111111111  parity=0  frame=00111111111111111110
```

> [!note] 对照检查
> - `target = 0` → 帧 = `001` `1000...0000` `1` ✅ 与 [[01-协议篇/02-帧结构详解]] 练习 2.1 一致
> - `target = 32767` → 帧 = `001` `1111...1111` `0` ✅ 与练习 2.2 一致
> - `target = -32768` → 帧 = `001` `0000...0000` `0` ✅ 与练习 2.3 一致

## 6. 常见编码错误

### 6.1 "除以 65535 还是 65536" —— 一个真实的 ±1 陷阱

这是动手实现时**必然遇到**的问题，两种写法都对，但结果差 1：

```text
写法 A： 发送值 = 比例 × 65535        ← 把区间 [0,1] 映射到 [0, 65535]
写法 B： 发送值 = 比例 × 65536        ← 把区间 [0,1) 映射到 [0, 65536)，然后截断到 65535
```

| 比例 | × 65535（写法 A） | × 65536（写法 B） | 差 |
|---|---|---|---|
| 0.125 | 8191.875 → **8191** `0x1FFF` | 8192 → 8192 `0x2000` | 1 |
| 0.500 | 32767.5 → **32768** `0x8000` | 32768 → 32768 `0x8000` | 0 ✅ |
| 0.625 | 40959.375 → **40959** `0x9FFF` | 40960 → 40960 `0xA000` | 1 |
| 1.000 | 65535 → 65535 `0xFFFF` | 65536 → **溢出** | ⚠️ |

**怎么选？**

| 场景 | 建议 |
|---|---|
| 只想"能跑、图形正常" | 两种都行，差 1 LSB 肉眼不可见（0.0006°） |
| 需要**端到端精确复现**别人的图形 | 必须和上位机用**同一种**写法 |
| 满量程边界 | ⚠️ 写法 B 在比例 = 1.0 时会溢出，**必须钳位** |

> [!tip] 💡 本库的推荐写法
> ```c
> /* 用 65535，并且钳位，最安全 */
> double norm = (angle - min) / (max - min);   /* 0.0 .. 1.0 */
> if (norm < 0.0) norm = 0.0;
> if (norm > 1.0) norm = 1.0;
> uint16_t v = (uint16_t)(norm * 65535.0 + 0.5);  /* 四舍五入 */
> ```
> 注意 `+ 0.5` 是四舍五入——不加的话会**向下取整**，让所有值系统性偏小半个 LSB。
> 这个偏差虽然小，但在做高精度标定时会变成系统误差。

> [!warning] ⚠️ 中心点是个特例
> 比例 = 0.5 时，`0.5 × 65535 = 32767.5`，四舍五入得 **32768 = `0x8000`** ✅ 正确。
> 但如果**不加 0.5 直接截断**，会得到 32767 = `0x7FFF`——**中心偏了 1 LSB**。
> 这会导致图形整体偏移，标定时怎么调都差一点点。
> **务必加 0.5 做四舍五入。**

### 6.2 其他错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 中心值用了 `0x0000` | 图形整体偏移，只有正半轴可用 | 中心应为 `0x8000` |
| 用补码而非偏移二进制 | 图形左右/上下反向 | 补码最高位取反 |
| LSB first 发送 | 图形完全错乱 | 改为 MSB first |
| `int16_t + 32768` 溢出 | 某些值错误 | 提升到 int32_t 再运算 |
| 忘了钳位 | 超范围值回绕，图形跳变 | 发送前 clamp 到 [−32768, 32767] |
| 角度用了机械角 | 图形尺寸差 2 倍 | 确认光学角/机械角 |
| 转换时忘了 `+0.5` | 系统性偏小 0.5 LSB，中心偏移 | 加 0.5 四舍五入 |

> [!danger] 钳位很重要
> 如果你的轨迹算法算出了 `+40000` 这样的越界值，
> 千万不要直接转 uint16（会回绕成负数，镜片**瞬间甩到另一端**，可能损坏振镜！）
> ```c
> if (v >  32767) v =  32767;
> if (v < -32768) v = -32768;
> ```

## 7. 动手练习 🔬

> [!example] 练习 4.1
> 满量程 ±10°（光学角），目标角度 +2.5°，求发送值。
>
> **解**：
> ```text
> 归一化 = (2.5 + 10) / (10 + 10) = 12.5 / 20 = 0.625
> 发送值 = 0.625 × 65535 = 40959.375 → 40959 = 0x9FFF
> ```
> 比例 0.625 正好是 5/8，直觉上你可能期望 `5/8 × 65536 = 40960 = 0xA000`，但实测是 `0x9FFF`。
> **这个 ±1 的差异见下面第 6.1 节**——这是本协议最容易踩的数值陷阱之一。

> [!example] 练习 4.2
> 收到发送值 `0x2000`，满量程 ±20°，求角度。
>
> **解**：
> ```text
> 0x2000 = 8192
> 比例 = 8192 / 65535 ≈ 0.125
> 角度 = −20 + 0.125 × 40 = −20 + 5 = −15°
> ```

> [!example] 练习 4.3
> 我要用一台 ±20° 振镜画一个 100 mm × 100 mm 的方框，场镜 f = 160 mm。
> 方框四个角的发送值是多少？
>
> **解**：
> 先算角度：`θ = r / f`（弧度）
> ```text
> 半边长 = 50 mm
> θ = 50 / 160 = 0.3125 rad = 17.90°
> ```
> 再算发送值：
> ```text
> +17.90° → (17.90 + 20)/40 = 0.9475 → 0.9475 × 65535 ≈ 62094 = 0xF28E
> −17.90° → (−17.90 + 20)/40 = 0.0525 → 0.0525 × 65535 ≈ 3441  = 0x0D71
> ```
> 四个角：`(0x0D71,0x0D71)`、`(0xF28E,0x0D71)`、`(0xF28E,0xF28E)`、`(0x0D71,0xF28E)`
>
> ⚠️ 注意：这个计算**忽略了 F-θ 场镜的畸变**，实际加工需要标定校正。
> 见 [[03-调试与排错篇/04-图形失真与标定]]。

## 8. 18 位模式的区别

增强模式下位置是 **18 位**，中心值变成 `0x20000`（131072）：

| 项目 | 16 位标准 | 18 位增强 |
|---|---|---|
| 数据位数 | 16 | 18 |
| 发送值范围 | 0 ~ 65535 | 0 ~ 262143 |
| **中心值** | `0x8000` (32768) | **`0x20000`** (131072) |
| 有符号范围 | −32768 ~ +32767 | −131072 ~ +131071 |
| 校验 | 偶校验 | **奇校验** |
| 分辨率提升 | — | **4 倍** |

> [!quote] sigrok 解码器源码
> ```python
> else:  # 18-bit
>     count = 17
>     for ss, es, value in self.bits[3:19]:
>         pos |= value << count
>         count -= 1
>     pos = pos if pos < 131072 else pos - 262144
> ```
> ⚠️ 注意：解码器在这个分支里只取了 16 个 bit（`bits[3:19]`），
> 这看起来是解码器自身的实现取舍（或 bug）。
> **以规范为准**：18 位模式应该是 1 位类型 + 18 位数据 + 1 位校验。
> 详见 [[01-协议篇/06-XY2-100E增强版]]。
