# 📄 XY2-100 协议速查（一页纸）

> [!tip] 打印建议
> Ctrl+P → 缩放选"适应页面" → **横向**。打完贴桌上。

---

## 🔢 核心参数

| 项目 | 值 |
|---|---|
| **标准编号** | **LasIA LIA202001** |
| 时钟频率 | **2 MHz**（必须连续运行） |
| 时钟周期 | 500 ns |
| 每帧位数 | **20 bit** |
| 帧长 | **10 μs** |
| 帧率 | **100 kHz**（100 kwords/s） |
| 比特率 | 2 Mbit/s |
| 数据采样沿 | **CLK 下降沿** |
| 数据变化沿 | **CLK 上升沿** |
| 帧开始 | **SYNC 上升沿** |
| SYNC 高电平 | **19 bit**（9.5 μs） |
| SYNC 低电平 | 1 bit（校验位期间） |
| tDS（建立） | ≥ **50 ns** |
| tDH（保持） | ≥ **100 ns** |
| 电气层 | **RS-422** 差分 |
| 位置位数 | 16（标准）/ 18（增强） |
| 校验 | 偶校验（标准）/ 奇校验（增强） |
| 位置编码 | 偏移二进制，中心 = `0x8000` |
| 终端电阻 | ⚠️ 标准无规定（XY3-100 才要求） |

## 🧩 帧格式（标准 16 位）

```text
发送次序:  1   2   3    4    5   …   18   19   20
         ┌───┬───┬───┬────┬────┬───┬────┬────┬────┐
CHANNELX │ 0 │ 0 │ 1 │D15 │D14 │ … │D01 │D00 │ P  │
CHANNELY │ 0 │ 0 │ 1 │D15 │D14 │ … │D01 │D00 │ P  │
         └───┴───┴───┴────┴────┴───┴────┴────┴────┘
           └控制字001┘ └── 16位数据 ──┘  偶校验
                        MSB first ↑先发
```

**增强 18 位**：`1` + `D17…D0` + **奇校验 Po**（共 20 位不变）

---

## ⚡ 校验位计算 ⚠️ 最容易错

```text
✅ 正确: P = XOR(C2, C1, C0, D15…D0)     ← 覆盖全部 19 个前导位
❌ 错误: P = XOR(D15…D0)                  ← 只覆盖 16 位
```

> [!danger] 因为控制字 `001` 含 **1 个 1**，两种算法**结果必然相反**！
> georgemihaila/xy2-100 和 OPAL 两个流行开源库都犯了这个错。

```c
uint32_t frame19 = (0b001u << 17) | (wire << 1);   // 19 位前导
uint8_t  parity  = __builtin_parity(frame19);      // 或循环异或
```

```verilog
wire par = ^frame19[19:1];   // Verilog 一行
```

## 🔢 关键编码值（可直接比对）

| target | 线上帧 | 20 bit |
|---|---|---|
| −32768 | `0x20001` | `00100000000000000001` |
| −12345 | `0x29F8F` | `00101001111110001111` |
| **0（中心）** | **`0x30000`** | **`00110000000000000000`** |
| 1 | `0x30003` | `00110000000000000011` |
| 30000 | `0x3EA61` | `00111110101001100001` |
| 32767 | `0x3FFFF` | `00111111111111111111` |

**换算**：`发送值 = target + 32768`

> [!note] 18 位模式中心值 = `0x20000`（131072）

## 📐 时序波形

```text
        ├── 一帧 10 μs (20 bit) ──┤
CLK     ┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐  连续不停
SYNC    ┌────────────────────────────┐
        │   高 19 bit                └────────
        ↑帧开始                    ↑校验位前拉低
DATA    ──<001>< D15…D0 ><P>──
              ↑上升沿变化  ↑下降沿采样
```

---

## 📌 信号线

| 信号 | 方向 | 说明 |
|---|---|---|
| CLK | 控制卡→振镜 | 2 MHz 连续 |
| SYNC | 控制卡→振镜 | 帧同步 |
| X | 控制卡→振镜 | X 轴数据 |
| Y | 控制卡→振镜 | Y 轴数据 |
| Z | 控制卡→振镜 | 可选（3D） |
| **STATUS** | **振镜→控制卡** ⚠️ | 状态回读，**不同步** |

**最少 4 对差分线**（CLK/SYNC/X/Y）

---

## ⚠️ 十一条铁律

1. **CLK 必须连续运行**，永不停
2. **帧之间无间隙**，背靠背
3. **位置不变也要继续发帧**（重复上一帧的值）
4. **X/Y 必须同一帧内同时发送**
5. **数据在上升沿变化、下降沿稳定**
6. **SYNC 高 19 位**，校验位期间为低
7. **校验覆盖 19 位**，不是 16 位
8. **MSB first**（D15 先发，D0 后发）
9. **中心值是 `0x8000`**（发送值），不是 0
10. **发送前必须钳位**，否则回绕会让镜片猛甩
11. 🚨 **换协议版本先查 CLK/SYNC 是否互换**（XY3-100 与 XY2-100 相反！）

> [!danger] 🚨 第 11 条展开：XY3-100 引脚陷阱
> | 协议 | Pin 1 / 14 | Pin 2 / 15 |
> |---|---|---|
> | XY2-100 | **CLK** | **SYNC** |
> | XY3-100 | **SYNC (A)** | **CLK (B)** |
>
> 帧起始边沿也相反。XY3-100 标准称"引脚兼容"**只在数据线上成立**。

## ✅ 发送流程伪代码

```c
send_frame(x_wire, y_wire):
    sync = HIGH                              // 帧开始
    for i = 19 downto 1:                     // 前 19 位
        if i == 0: sync = LOW                // 实际在最后一位前拉低
        data = (frame >> i) & 1
        clk = HIGH   // 数据在此变化
        clk = LOW    // 振镜在此采样
    sync = LOW                               // 校验位期间
    data = parity_bit
    clk = HIGH; clk = LOW
    // 立即开始下一帧, 无间隙
```
