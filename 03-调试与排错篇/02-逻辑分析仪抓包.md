# 🎯 逻辑分析仪抓包

> [!success] 这是本知识库最实用的一篇
> **¥20 的 USB 逻辑分析仪 + 免费的 PulseView（sigrok）+ 内置的 XY2-100 解码器**
> = 一秒读出振镜收到的每一帧数值，自动检查校验位，自动标出警告。
>
> 没有这个工具，调 XY2-100 会难 10 倍。

## 2. 接线

### 最少 3 根线就能解码

| 分析仪通道 | 接到 | 必需性 |
|---|---|---|
| **D0** | **CLK+** | ⭐ 必需 |
| **D1** | **SYNC+** | ⭐ 必需 |
| **D2** | **X+** 或 **Y+** | ⭐ 必需（看一根轴） |
| D3 | STATUS+ | 可选（解码状态字） |
| D4 | Y+ | 可选（同时看两轴） |
| **GND** | **控制卡 GND** | ⭐ 必需 |

```text
   逻辑分析仪
   ┌──────────┐
   │ D0 ──────┼──── CLK+
   │ D1 ──────┼──── SYNC+
   │ D2 ──────┼──── X+
   │ D3 ──────┼──── STATUS+  (可选)
   │ GND ─────┼──── 控制卡 GND
   └──────────┘
```

> [!danger] ⚠️ 两个注意点
> 1. **GND 必须接**！不接地的话信号全是噪声。
> 2. 逻辑分析仪的输入是**单端**的，接 **P 端（正端）** 即可。
>    不要把 P 和 N 同时接到两个通道上（除非你想看差分关系）。

## 3. PulseView 配置步骤

### 步骤 1：选择设备

```
PulseView → 顶部工具栏 → 设备下拉 → fx2lafw (USB) → 选你的设备
```

### 步骤 2：设置采样参数

| 参数 | 推荐值 | 说明 |
|---|---|---|
| **采样率** | **24 MHz** | 越高越好，但 24M 是上限 |
| **采样数** | **1 M 采样** | = 约 41 ms = 约 4000 帧 |
| **通道数** | 4（用到的） | |

> [!tip] 💡 采样率怎么选
> 要看清 2 MHz 的 CLK，采样率至少要是它的 **10 倍**（20 MHz）。
> 24 MHz 正好够用 → 每个 CLK 周期采到 **12 个点**。
>
> 想看清边沿的细节（比如建立时间），24 MHz 就不太够了（分辨率 41 ns）。
> 那种情况下要用示波器。

### 步骤 3：添加解码器

```
菜单 → Add decoder → 搜索 "XY2-100" → 选中
```

**配置解码器信号映射**：

| 解码器输入 | 分配的通道 |
|---|---|
| **CLK** | D0 |
| **SYNC** | D1 |
| **DATA** | D2 |
| **STAT（可选）** | D3 |

### 步骤 4：采集

点 **Run** → 让设备发几帧数据 → 点 **Stop**

## 4. 解码器会告诉你什么

sigrok 的 XY2-100 解码器内置了这些注解行：

| 注解行 | 内容 |
|---|---|
| **Data Bits** | 每一位的值（0/1） |
| **Status Bits** | STATUS 线的位 |
| **Data** | **帧类型**（16 bit / 18 bit / Command）、**Command**、**Parameter**、**Parity 状态** |
| **Positions** | **解码出的位置值**（有符号数） |
| **Statuses** | 解码出的状态字（十六进制） |
| **Warnings** | ⚠️ **校验错误、数据位不足、未知命令** |

> [!success] 最有用的三个输出
> 1. **`Positions` 行直接显示位置值** —— 和你代码里发送的值对比即可验证编码
> 2. **`Parity` 显示 `OK` / `NOK`** —— 一秒验证你的校验位算法
> 3. **`Warnings` 显示 `Parity error`** —— 直接告诉你校验错了

### 解码器源码里的关键逻辑

```python
# 采样: CLK 下降沿取数据
else:                       # clk == 0, 下降沿
    bit_value = data
    sync_value = sync

# 校验: 前 19 位异或
parity = 0
for ss, es, value in self.bits[:-1]:
    parity ^= value

# 位置: MSB first 拼接, 再转有符号
count = 15
for ss, es, value in self.bits[3:19]:
    pos |= value << count
    count -= 1
pos = pos if pos < 32768 else pos - 65536
```

本地源码：`99-附件与下载/代码/sigrok-xy2-100-decoder/pd.py`

## 5. 五个实战用法

### 用法 1：验证位置编码

**做法**：
1. 程序里发送固定值（例如让 X = 0）
2. 抓包看 `Positions` 行的值
3. 应该显示 `0`

| 你发送的目标值 | 线上帧（hex） | PulseView 显示 |
|---|---|---|
| −32768 | `0x20001` | **−32768** |
| 0（中心） | `0x30000` | **0** |
| +32767 | `0x3FFFF` | **32767** |

> [!warning] ⚠️ 屏幕上显示的是"有符号值"，不是线上的 hex
> 解码器把 20 bit 拆出 16 位数据后**转成了有符号数**。
> 所以你会看到 `-32768 … +32767`，而不是 `0x3xxxx`。
> 两者是同一个东西的不同视角。

**如果显示的值不对**：
| 现象 | 原因 |
|---|---|
| 数值是"反的"（正负颠倒） | 用了补码而不是偏移二进制 |
| 图形镜像 | 差分 P/N 接反 |
| 值完全乱 | LSB/MSB 顺序错 |
| 总是差 1 | 索引/计数器错开一位（我在 RTL 里踩过这个坑） |

### 用法 2：验证校验位 ⭐

**做法**：
1. 看 `Parity` 注解行
2. 显示 `OK` → 正确 ✅
3. 显示 `NOK` → 校验错了 ❌

> [!success] 一秒定位那个"两个开源库都踩的坑"
> 如果你发现所有帧都是 `NOK`，**几乎肯定是你只对 16 位数据求了校验**，
> 而正确的做法是**对前 19 位（含控制字）求校验**。
>
> 见 [[01-协议篇/02-帧结构详解]] 的校验范围一节。

### 用法 3：验证 SYNC 时序

**做法**：
1. 在波形区放大到能看清一个 SYNC 脉冲
2. 数 SYNC 高电平期间有几个 CLK 周期
3. 应该是 **19**

**如果数出 20**：说明 SYNC 拉低时机晚了一个位。

### 用法 4：验证帧连续性

**做法**：
1. 缩小波形（看几百 μs）
2. 观察 SYNC 是否**等间隔**出现
3. 中间不应有空档

**如果有空档**：你的程序没有持续发送（违反了"时钟不能停"的要求）。

### 用法 5：读 STATUS 状态字 ⭐

**做法**：
1. 把 **STATUS+** 接到 D3
2. 解码器配置里给它分配 `STAT` 通道
3. 看 `Statuses` 行

**能读到什么**：
- 伺服是否就绪
- 温度是否告警
- **跟踪误差是否超限** ← 优化速度参数的关键！
- 通道校验错

> [!tip] 💡 这是优化加工参数最快的办法
> 把 **tracking error 位**和你的**轨迹数据**一起抓，
> 就能精确看到**轨迹的哪一段让振镜跟不上了**。
> 比反复试参数快得多。

**注意**：STATUS **不与时钟同步**，解码器用了特殊处理（采样上升沿、跳过第一位）。
如果你的振镜不提供状态字，会读到全 1 或解码失败——这是正常的。

## 6. 拿"已知正确的设备"当参照

> [!success] ⭐ 这是最有价值的一招
> 如果你手边有一台**能正常工作的**控制卡（正运动 / JCZ / halaser 等）：
>
> 1. 用它驱动振镜
> 2. **抓一份正确的波形存档**
> 3. 再用你自己的板子驱动，抓同样的波形
> 4. **两条波形逐位对比**
>
> 差异点就是你的 bug 所在。
>
> 这比读一百篇文档都管用——**你有了一个绝对正确的基准**。

## 8. 常见问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 抓到的全是噪声 | **GND 没接** | 接地 |
| 信号一直是低 | 通道接错 / 探针没接触好 | 用万用表查通断 |
| 解码器没有输出 | 通道映射配错 | 检查 CLK/SYNC/DATA 分配 |
| 解码出 `Not enough data bits` | SYNC 时序不对 | 检查 SYNC 是否为 19 位 |
| 解码出 `Unknown command or parity error` | 校验错或头部错 | 查校验范围、MSB 顺序 |
| 位置值全都一样 | 你的程序没更新位置 | 检查是否真的在改目标值 |
| 采样深度不够 | 采样数设太小 | 增大到 1 M 或更高 |
| 波形看不清边沿 | 采样率不够 | 24 MHz 已是这款上限，细节用示波器 |
