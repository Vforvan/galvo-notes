# 🔄 逆运动学与雅可比

> [!info] 一句话版本
> 正向是"**给我五个转角，我算焦点在哪**"；逆向是"**我要焦点在这个位姿，你告诉我五个转角该多少**"。
> 四镜系统里这两件事**没有闭式解** —— 四个转角对五个输出量强耦合，
> 唯一可行的办法是：**猜一个初值 → 算误差 → 沿雅可比方向修正 → 重复**。

---

## 1. 为什么不能像两轴振镜那样"反三角一下"

两轴振镜太简单了，`θx = atan(x/f)`、`θy = atan(y/f)`，一行公式搞定。

五轴系统不行，原因有三条：

| 原因 | 说明 |
|---|---|
| **耦合** | 四个转角都同时改落点和方向。`q₁` 动一下，X 和 α 都变 |
| **非线性** | 反射是"减两倍法向分量"，法向又随转角做 Rodrigues 旋转 → 三角函数套三角函数 |
| **有边界** | 转角有机械上限、焦点有行程上限，解必须在**闭区间**内 |

> [!danger] 别把"两轴的反三角"硬套到五轴上
> 网上很多"振镜控制"代码是两轴的，公式短、能直接反解。
> 一旦轴数到 4，**那些公式全部失效** —— 不是精度问题，是结构问题。

---

## 2. 雅可比：把"非线性"局部拉直

在某个工作点 `q` 附近，做一阶泰勒展开：

```text
ΔT ≈ J(q) · Δq          J 是 5×5 矩阵，ΔT 是 5 维位姿误差
```

`J` 的每一列回答："**第 i 个指令动一点点，五个输出各动多少**"。

本项目**不解符号导数**，用**中心差分**求数值雅可比：

```text
J[:, i] = ( F(q + δ·eᵢ) − F(q − δ·eᵢ) ) / (上界 − 下界)
δ = 1e-6
```

> [!warning] 边界处理是这段代码唯一的坑
> 如果 `q[i]` 正好顶在机械行程的边界上，
> **`q + δ` 就越界了，`forward()` 会直接抛 `ValueError("Command exceeds machine limits")`**。
>
> 所以代码先做裁剪：
> ```text
> lower = max(机械下界, q[i] − δ)
> upper = min(机械上界, q[i] + δ)
> span  = upper − lower          ← 实际用的步长，可能小于 2δ
> if span ≤ 0:  抛 "Cannot evaluate Jacobian at a fixed bound"
> ```
> **注意除的是真实 `span` 而不是 `2δ`** —— 否则贴边时雅可比会被系统性缩小。

## 3. 秩 5：五维能解的前提

标称点 `q = [0,0,0,0,0.075]` 处，`J` 的奇异值：

```text
[2.6994, 2.1889, 1.0007, 0.0504, 0.0429]
```

| 观察 | 含义 |
|---|---|
| 全部 > 0 → **秩 5** | 五个自由度**可以独立指定**，这是五轴补偿成立的前提 |
| 最大/最小 ≈ **63 倍** | `α/β` 两个方向"很软"，需要很大转角才撬动一点角度 |
| 条件数大 | 数值上敏感：目标 `α/β` 给错一点点，解出来的 `q` 差很多 |

> [!tip] 为什么"满秩"值得专门写一条测试
> `tests/test_kinematics.py::test_jacobian_is_full_rank` 是**契约测试**。
> 谁改了镜面中心、转轴或初始法向，只要把秩改掉了，测试立刻红 ——
> 因为秩掉到 4 就意味着"有一维根本控不了"，整个五轴补偿的立论就没了。

## 4. 求解器：有界 `least_squares`

```text
目标 T
  │
  ├─ 残差函数 objective(q) = pose_residual(F(q), T) / scales
  │     ├─ 角分量做 atan2(sin·, cos·) 回绕，避免 ±π 跳变
  │     ├─ scales = [pos_scale]×3 + [ang_scale]×2
  │     │     pos_scale = max(position_tolerance, 1e-5)
  │     │     ang_scale = max(angle_tolerance,    1e-5)
  │     └─ 捕获 GeometryError → 返回常数 np.full(5, 1e6)
  │
  └─ scipy.optimize.least_squares(
         bounds = (machine.lower_bounds, machine.upper_bounds),
         max_nfev = 150,
         xtol = ftol = gtol = 1e-12)
```

### 4.1 四两拨千斤的三处设计

| 设计 | 解决什么问题 |
|---|---|
| **残差按位置/角度分开缩放** | 位置量级 ~1e-3 m，角度量级 ~1e-3 rad，但容差不同。不缩放会让优化器只顾一个方向 |
| **角分量 `atan2(sin,cos)` 回绕** | 目标 α=+179°、实际 α=−179° 时，朴素相减得 358°，优化器会往反方向跑一整圈 |
| **`GeometryError → 1e6`** | 优化器试探到不可达区域（打飞镜面、光线反向）时，不能让程序崩，要得到一个"很大的残差"把它**推回可行域** |

> [!danger] `1e6` 这个数不是随便写的
> 它必须**远大于**任何真实残差（真实残差量级 1e-3），
> 又要**足够小**不至于让 `least_squares` 的数值微分失真。
> 1e6 相对残差尺度（缩放后 ~1）大了六个数量级，是安全区。

### 4.2 收敛判据是"两条都要满足"

```text
success = 求解器自报成功
          并且 ‖残差[:3]‖ ≤ position_tolerance     位置三轴
          并且 ‖残差[3:]‖ ≤ angle_tolerance        角度两轴
```

默认容差 **1e-6**（米 / 弧度）。补偿链路里用的是更松一点的 **2e-6**
（`PolynomialCompensator.solve_command` 里写死）。

> [!warning] 求解器"成功"不等于"解对了"
> `scipy` 的 `success` 只说"我收敛了"，可能收敛到一个**局部极小**，
> 也可能停在边界上离目标还很远。
> 所以必须**自己再验一遍残差**。这也是 `InverseKinematicsResult` 要同时带
> `success` / `residual` / `achieved_pose` / `message` 四个字段的原因。

## 5. 初值给谁：一个容易忽略的细节

```python
initial = initial_command if initial_command is not None \
          else [0, 0, 0, 0, machine.specifications.objective_focal_length_m]
initial = np.clip(initial, lower_bounds, upper_bounds)
```

| 场景 | 用的初值 |
|---|---|
| 标定 / 验证（离线批量） | 不传 → 用标称点 `[0,0,0,0,0.075]` |
| 补偿求解（在线） | 传**当前滑块指令** → 热启动，快且稳 |
| 页面手动逆解 | 传当前指令 |

> [!tip] 为什么初值重要
> 工作域很窄（见 [[05-五轴与补偿篇/运动学模型/01-正向运动学：镜面链与位姿解算]] 第 4 节），
> 从标称点出发通常没问题；但**贴边目标**从远处起步容易落进 1e6 的"墙"里出不来。
> 用当前指令做热启动是最省事的稳健化手段。

## 6. 完整数据流：从目标到位姿误差

```text
目标位姿 T
   │
   ├─① 补偿矩阵迭代反推"理想机该走到哪"
   │     p ← T
   │     重复 3 次:  p ← T − predict(p)
   │     corrected ← p
   │
   ├─② 让【理想机】逆解出能到 corrected 的指令
   │     inverse_kinematics(ideal, corrected,
   │                        initial_command = 当前指令,
   │                        position_tolerance = 2e-6,
   │                        angle_tolerance = 2e-6)
   │
   ├─③ 把这条指令交给【真实机】执行
   │     after = real.forward(corrected_command)
   │
   └─④ 与原始目标比较
         errors_after = pose_residual(after.pose, T)
```

> [!danger] 注意第 ② 步用的是**理想机**逆解
> 这是补偿的核心思想：**让理想机去走一个被提前"偏置"过的目标**，
> 使得真实机执行同样指令时，恰好落在真正的目标上。
> 用真实机逆解当然更准，但那需要已知真实机误差 —— 实机上恰恰不知道，
> 才需要补偿模型。用真实机逆解只作**仿真参考**，不代表实机可做到。

## 8. 边界：逆解只管几何，不管动力学

> [!warning] 这一节很重要，别把静态几何解当成"能跑多快"
> 逆解算出来的是**静态最优指令**，它只知道"转到这个角度，光就落在这里"。
> 它**完全不知道**：
> - 振镜从上一个点转到这个点要多久（伺服带宽、阶跃响应）
> - 转过去会不会过冲、有没有跟随误差
> - 650 Hz 的环切能不能跟上
>
> 这些属于**动力学**，本平台**没有建模**。
> 想接上这一层，去 [[02-硬件实现篇/05-更新率与振镜带宽匹配]]：
> 那里讲了"100 kHz 帧率 ≠ 能跑 100 kHz"，以及带宽是怎么从时域指标反推的。
