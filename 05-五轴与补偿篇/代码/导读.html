0一句话说清

如果只能记住一段，记这段。它能应付大部分追问。

核心一句话

这个项目把「五轴振镜的指令 q」到「光束的实际落点姿态 T」之间的映射做成了数字孪生。 因为真机存在装配误差，同一条指令真机走不到理想位置；于是先用理想机和真机跑 400 组对照数据， 拟合出一个 21×5 的二阶多项式误差模型，再把目标位置反向修正一次 —— 位置误差从 64.9 μm 降到 0.002 μm。

两个 5 维向量

q = [q1, q2, q3, q4, qf]   # 我下发的指令
     └─ 4 个镜子的转角(rad) ─┘ └ 光程(m)

T = [X, Y, Z, α, β]        # 光束实际打到哪
     └─ 焦点位置(m) ─┘ └ 倾角(rad)

为什么叫「5D」

因为有 5 个输入（4 个转角 + 1 个光程）和 5 个输出 （3 个位置 + 2 个角度），不是 5 个轴。补偿要同时管住这 5 个分量， 让它们一起对准目标。

1到底在解决什么问题

不先想清楚这个，后面所有代码都像在无病呻吟。

理想情况 vs 真实情况

假设你告诉振镜「转角 0.008 rad」。如果镜子的位置、转轴、零位都完美， 光会精确落在某个点。但真机上：

误差来源物理含义本项目取值
position_offsets镜子装偏了，不是理论位置N(0, 20 μm)
axis_tilts转轴歪了N(0, 100 μrad)
zero_offsets零位标定不准N(0, 50 μrad)
focal_scale/offset焦距有比例/偏置误差1.0002 / 20 μm
后果：同一指令，两台机器走出两个位置

实测指令 q=[0.008, −0.008, 0.001, 0.0005, 0.0748]： 理想机落点 [10314.09, 2308.85, 1140.12] μm， 真机落点 [10365.85, 2298.17, 1102.72] μm。

位置差了 64.74 μm，姿态差了 232.02 μrad。 对一个理论分辨率 20 nm 的设备，这个偏差大了三个数量级，必须补偿。

补偿的思路：把目标「反向挪一下」

既然「下发 q → 真机落到 A，而我想去 B」，那就不要下发 q，改下发一条修正过的指令 q′， 使得真机执行 q′ 之后正好落在 B。

① 目标 B
我想要光束落在 B 点
▼
② 问误差模型：如果真机走在 B，它会偏多少？
用拟合出的多项式预测偏差 Δ = f(B)
▼
③ 那就把理想机的目标挪到 B − Δ
让真机从「偏后的位置」正好偏回 B
▼
④ 逆解出指令 q′ 并下发
真机执行 q′，落点回到 B，误差被抵消

注意第 ② 步是个不动点问题：偏差 Δ 依赖于「理想机到哪」，而理想机到哪又取决于 Δ。 所以代码里用 3 次迭代收敛（见第 4 节）。

3数据怎么流

这张图看懂，整个项目就通了。两条路：一条正向、一条逆向。

正向：指令 → 位姿（model.forward）

输入指令 q[5]
4 个转角 + 1 个光程
▼
逐级遍历 M1 → M4，每面镜子做 4 件事
center ← 理论位置 + 安装位置偏置
axis ← 转轴 + 轴倾斜（再归一化）
normal ← 绕 axis 旋转 mirror.normal，角度 = q[i] + 零偏
hit ← 光线与镜面求交
▼
三道几何检查（任一失败就抛 GeometryError）
① 命中点离镜心 > 孔径 5 mm → Ray misses mirror i aperture
② 光线与镜面平行 → Ray is parallel to mirror plane
③ 交点在光线反方向 → Mirror intersection is behind the ray origin
▼
反射并前进
direction ← reflect(direction, normal)，origin ← hit
▼
4 面镜子走完，算焦点
focus_distance ← q[4] × focal_scale + focal_offset
focus ← origin + focus_distance × direction
▼
输出位姿 T[5] = [X, Y, Z, α, β]
α = atan2(d.x, −d.z)，β = atan2(d.y, −d.z)；d.z ≥ 0 时抛错（出射光必须朝 −Z）
关键理解：误差是在哪一步注入的？

全部注入在「算镜面法向」之前的准备步骤里 —— 位置偏置加在镜心、 轴倾斜加在转轴、零偏加在转角上。reflect() 和求交本身是纯几何、无误差的。

所以理想机和真机用的是同一份代码，唯一区别是 errors 字段： 理想机全为零，真机填了随机误差。create_default_machine(errors=None) 就是理想机。

逆向：位姿 → 指令（kinematics.inverse_kinematics）

给定目标位姿 T，要反推 q。这是非线性问题（镜面旋转与落点不是线性关系），所以用数值优化：

目标 T
▼
构造残差函数
residual(q) = pose_residual(forward(q), T) / 尺度
角分量做 atan2(sin, cos) 回绕，避免 ±π 跳变；
几何失败时返回常数 1e6，把解推回可行域。
▼
scipy.optimize.least_squares 迭代
bounds=[lower, upper]，max_nfev=150，xtol/ftol/gtol=1e-12
▼
输出 q′ + success 标志
success = 求解器成功 且 位置残差 ≤ tol 且 角度残差 ≤ tol
为什么这里能解出唯一答案

因为标称点处的雅可比矩阵满秩（秩 = 5），奇异值为 [2.6994, 2.1889, 1.0007, 0.0504, 0.0429]，全部非零。 5 个输入正好能独立控制 5 个输出，不多不少。

这也是 tests/test_kinematics.py::test_jacobian_is_full_rank 把守的契约 —— 如果改镜面布局把这个秩搞掉了，测试会立刻红。

4「5D 补偿矩阵」是怎么生成的

这是项目标题的核心，也是最容易被问的地方。建议逐字读完本节。

它到底是什么

先纠正一个常见误解

它不是几何矩阵，也不是 5×5。 它是一张 21×5 的多项式系数表： 输入目标位姿，输出「真机会偏多少」这个 5 维误差向量。 

# 模型的数学形式
x           = (T − center) / scale        # 先把位姿标准化
features(x) = 21 个基函数                  # 见下
errors(T)   = features(x) @ C   ∈ R⁵      # C 的形状是 21×5
              └─ 预测 [ΔX, ΔY, ΔZ, Δα, Δβ]

21 个基函数怎么来的

「二阶多项式」在 5 维输入下展开，项数 = (n+1)(n+2)/2，代入 n=5 得 21：

类别项数具体
常数项11
一次项5x0, x1, x2, x3, x4
二次项15x0², x0x1, … , x3x4, x4²
合计21—

离线标定：7 步生成

① 随机撒指令
q[0:4] ~ U(−2.06°, +2.06°)，q[4] ~ U(0.074, 0.076) m
▼
② 同一条指令喂给两台机器
ideal_pose = ideal.forward(q) ／ real_pose = real.forward(q)
得到「同一输入下的位姿差」
▼
③ 过滤无效样本
几何失败 → 丢弃；理想位姿超出工作域 → 丢弃
存活率只有约 5.7%（见第 5 节），所以源码里留了 30 倍尝试次数
▼
④ 组装标定数据 → 相减得到误差标签
commands / ideal_poses / real_poses 各 400×5
errors = real_poses − ideal_poses → 400×5
▼
⑤ 标准化（这一步不能省）
center = mean(ideal_poses)，scale = std(ideal_poses)，x = (ideal_poses − center) / scale
▼
⑥ 造特征 + 最小二乘 ← 矩阵在这里诞生
A = _quadratic_features(x) → 400×21
C, *_ = np.linalg.lstsq(A, errors, rcond=None) → C 是 21×5
▼
⑦ 独立验证
用 seed+1 的新采样命令测补偿前后 RMSE，报告成功/失败数
先排掉一个最容易踩的坑：标定阶段不做逆解

一个很自然的误解是：拿到「有误差位姿」之后，把它丢给理想机做逆解，算出修正后的指令 q′， 再去拟合。这条路线行不通，而且代码里也确实没这么做。

原因一：拟合模型里根本没有 q。误差模型学的是 理想位姿 → 误差，不是 q → 误差。 所以「两个 q 怎么处理」这个问题不存在 —— q 在收集完数据后就退场了。

原因二：逆解不产生误差标签。误差标签只能来自减法 real_pose − ideal_poses。实测把真机位姿丢给逆解，会得到 q″ = [0.006473, −0.004419, 0.002506, −0.002142, 0.075239]， 而原指令是 [0.006, −0.005, 0.003, −0.002, 0.0752] —— 转一圈只是回到原指令附近（差 5e-4 量级），手里还是「一条指令」， 并没有多出「一个误差向量」。

记忆口诀：离线标定是「正正相减」，在线补偿才用「逆解」。

第 ④⑤⑥ 步详解（含源码）

这三步是整个补偿矩阵的诞生过程。每一步都给出真实代码和实跑数据。

第 ④ 步：组装标定数据 —— 误差标签从哪来

收集阶段得到三样东西：commands（撒出去的 q）、 ideal_poses、real_poses。真正进入模型的是后两者的差。

源码 calibration.py 第 12-22 行

@dataclass(frozen=True)
class CalibrationData:
    commands:    NDArray[np.float64]   # 400 x 5  撒出去的 q（收集完就退场）
    ideal_poses: NDArray[np.float64]   # 400 x 5  理想机位姿   -> 将来当输入 X
    real_poses:  NDArray[np.float64]   # 400 x 5  有误差位姿

    @property
    def errors(self) -> NDArray[np.float64]:        # 400 x 5  -> 将来当标签 y
        values = self.real_poses - self.ideal_poses
        # 角分量是周期量，直接相减可能得到 2*pi - eps 这种假大值
        # 用 arctan2(sin, cos) 把结果绕回 (-pi, pi]
        values[:, 3:] = np.arctan2(np.sin(values[:, 3:]), np.cos(values[:, 3:]))
        return values

第三行就是前两行逐个分量相减的结果（单位：位置 m、角度 rad）。 commands 在这里完全没有参与。

为什么要做角度回绕

角度是周期量。0.001 rad 和 0.001 + 2π rad 是同一个姿态， 但直接相减会得到 6.28 这么大的「误差」，把训练数据污染掉。 arctan2(sin(θ), cos(θ)) 是把它折算回 (−π, π] 的标准做法。

第 ⑤ 步：标准化 —— 为什么不做这一步角度补偿会废掉

源码 compensation.py 第 30-37 行（fit 的前半段）

def fit(self, data: CalibrationData) -> "PolynomialCompensator":
    # 中心：400 个理想位姿逐维求平均，得到 5 维向量
    self.center = np.mean(data.ideal_poses, axis=0)
    # 尺度：逐维标准差，同样 5 维
    self.scale  = np.std(data.ideal_poses, axis=0)
    # 保护：某一维几乎不变时标准差≈0，除法会炸出 inf/nan
    self.scale[self.scale < 1e-12] = 1.0
    # 标准化
    normalized = (data.ideal_poses - self.center) / self.scale

标准化之后，每一维都变成「均值 0、标准差 1」，这才是能一起比较的坐标。

不做标准化会怎样

看 scale 这行：Z 分量是 5.43e-4，角度分量是 1.51e-2， 差了 28 倍。

最小二乘最小化的是未加权的平方误差。如果不标准化， 量级大的分量（角度）会在目标函数里占据压倒性权重， 拟合器会几乎只照顾角度，Z 方向的补偿就等于被放弃了。

标准化把 5 个分量拉到同一尺度，让最小二乘「公平地」对待每一个分量。

顺带理解 center 的作用：它让「标准化后的中心位姿」落在原点 (0,0,0,0,0)，于是常数项系数直接就是中心点的平均误差。第 ⑥ 步会验证这一点。

第 ⑥ 步：造特征 + 最小二乘 —— 21×5 在这里诞生

这一步分两小步：先把 5 维位姿展开成 21 维特征， 再用最小二乘求出 21×5 的系数。

⑥-A　把 5 维展开成 21 维

源码 compensation.py 第 13-21 行

def _quadratic_features(values: NDArray[np.float64]) -> NDArray[np.float64]:
    if values.ndim != 2 or values.shape[1] != 5:
        raise ValueError("Expected an N x 5 feature matrix")
    # 第 1 列：常数项，恒为 1
    columns = [np.ones(values.shape[0])]
    # 第 2-6 列：5 个一次项 x0 .. x4
    columns.extend(values[:, index] for index in range(5))
    # 第 7-21 列：15 个二次项，只取上三角 (row <= column) 避免重复
    # 例如 x0*x1 与 x1*x0 是同一项，只保留一个
    for row in range(5):
        for column in range(row, 5):          # 注意从 row 开始，不是 0
            columns.append(values[:, row] * values[:, column])
    # 21 列横向拼成矩阵
    return np.column_stack(columns)
项数为什么正好是 21

1（常数）+ 5（一次）+ 15（二次）= 21。二次项的 15 来自「5 个变量取两个、允许重复」的组合数 C(5+2−1, 2) = 15，等价于公式 (n+1)(n+2)/2 = 21（n=5）。

代码里内层循环从 row 开始而不是 0，正是为了只取上三角 —— 否则会把 x0x1 和 x1x0 算两遍，变成 25 项且列之间完全共线。

⑥-B　最小二乘求解 → 21×5

源码 compensation.py 第 34-37 行

    normalized = (data.ideal_poses - self.center) / self.scale
    features   = _quadratic_features(normalized)      # 400 x 21   -> 记作 A
    # 解 A @ C = errors，求 C。A 是 400x21（超定），errors 是 400x5
    # 所以 C 的形状是 21 x 5：21 行对应 21 个基函数，5 列对应 5 个误差分量

读 lstsq 这一行的正确姿势

它解的是矩阵方程 A @ C = errors，其中 A 是 400×21、 errors 是 400×5。未知数 21 个、方程 400 个，是超定的， 没有精确解，所以 lstsq 返回使 ‖A@C − errors‖ 最小的那个 C。

返回的 C 自然是 21×5：21 行 = 21 个基函数的系数， 5 列 = 分别拟合 5 个误差分量。5 列是各自独立求解的， 这正是「位置和姿态能被一起修好」的原因。

代码里写成 self.coefficients, *_ = ...，是因为 lstsq 还返回残差平方和、秩、奇异值，这里只要第一个。 rcond=None 表示用机器精度作为判定「小奇异值」的阈值。

一个可以自查的漂亮性质：常数项 = 中心点的平均误差

因为第 ⑤ 步让各维均值为 0，「标准化后的中心位姿」正好是 (0,0,0,0,0)， 此时所有非常数基函数都为 0，预测值就只剩常数项。所以 C 的第 0 行 应该等于 errors 的列均值。实测：

⑥-C　拿到 C 之后怎么用：predict

源码 compensation.py 第 43-54 行

def predict(self, poses: ArrayLike) -> NDArray[np.float64]:
    if not self.fitted:
        raise RuntimeError("Compensator has not been fitted")
    values = np.asarray(poses, dtype=np.float64)
    # 兼容两种调用：单个位姿 (5,) 或一批位姿 (N, 5)
    scalar = values.ndim == 1
    if scalar:
        values = values[np.newaxis, :]
    if values.ndim != 2 or values.shape[1] != 5:
        raise ValueError("Pose input must have shape (5,) or (N, 5)")
    # 用训练时存下的 center/scale 做同样的标准化，然后走同一套 21 项特征
    normalized = (values - self.center) / self.scale
    prediction = _quadratic_features(normalized) @ self.coefficients   # (N,21)@(21,5) -> (N,5)
    return prediction[0] if scalar else prediction
两处必须注意

① center/scale 必须复用训练时的值。 它们被存在实例上（第 27-28 行），预测时不能再从新数据重算 —— 否则同一个位姿在训练和推理时会映射到不同的坐标，模型立刻失效。

② 参数名是 poses，没有 q。 这个签名本身就说明了问题：误差模型的输入是位姿，不是指令。 这也再次印证了前面那个坑 —— 标定阶段根本不需要处理「两个 q」。

为什么第 ① 步要迭代 3 次？

因为 predict 的自变量是「理想机应当到达的位置」， 而不是最终目标 T。这就成了不动点问题：想知道该挪多少，得先知道挪到哪。

好消息是收敛极快（平方收敛）。实测相邻两轮的修正量变化： 第 2 轮 6.7e-8，第 3 轮 6.2e-11，第 4 轮 8.8e-14。 所以代码里固定迭代 3 次就足够。

✓ 实际

是 21×5 的多项式系数表，把位姿映射成误差，跟几何变换无关

✗ 以为

✓ 实际

同一份代码，唯一区别是 errors 字段填没填。误差只注入在镜心/转轴/转角三处

✗ 以为

✓ 实际

受标记视场 2.5 mm 限制，单轴实际只有 0.6°~1.1°，小一个量级

✗ 以为

补偿是「给指令加个固定偏移」

✓ 实际

✗ 以为

残差 0.002 μm 说明设备精度是 0.002 μm

✓ 实际

8可能被追问的问题

点开看答案。建议先自己想一遍再点。

为什么用多项式，不用查表或神经网络？

查表需要存储海量格点，且格点之间要插值；神经网络参数多、需要更多样本、还难以解释。

多项式的好处：① 对系数是线性的，最小二乘一步求解，不需要迭代和初值； ② 只有 21 个参数，配 400 样本超定 19 倍，不易过拟合； ③ 物理上，小的几何误差对位姿的影响本来就近似低阶光滑函数，二阶足够。

实测佐证：400 样本和 800 样本得到的系数矩阵只差 0.06%，说明模型容量已经够用。

为什么是二阶，不是一阶或三阶？

一阶（6 项）不足以描述——误差里含 q² 性质的项（镜面旋转对落点的影响本身带三角函数非线性）。 三阶在 5 维下要 56 项，参数变多但对残差的改善已经进入噪声量级。

更直接的证据：加上二阶项后残差从 几十 μm 降到 0.002 μm， 跨越了 4 个数量级，说明二阶基函数已经抓住了误差的主要结构。

为什么必须先标准化再拟合？

因为 5 个位姿分量量级差得远。实测 scale = [1.2e-3, 1.2e-3, 5.4e-4, 1.5e-2, 1.5e-2]， 位置分量在毫米级、角度在毫弧度级，相差约 10 倍以上。

最小二乘最小化的是未加权的平方误差，量级大的分量会主导拟合， 角度方向的补偿精度就会很差。标准化让各分量处于同一尺度。

注意 scale 里还做了保护：小于 1e-12 的置为 1，避免除零。

怎么保证补偿不会「假装有效」？

四道防线：

① 训练/验证分离：验证用 seed+1 独立采样，与训练样本不重叠；

② 工作域门禁：is_pose_within_workspace() 不通过就直接停用补偿， 页面会显示「当前目标超出标定工作域」，而不是给出不可信的改善；

③ 逆解失败不显示：solution.success == False 时 after 保持 None；

④ 报告失败数：验证结果里带 failed_validation_samples，不藏失败的样本。 实测 80 点全部成功、0 失败。

forward() 是整个项目的真值来源，它可靠吗？

它可靠的部分：纯几何计算（旋转、求交、反射），每个函数都有单元测试把守， 例如 45° 反射的精确值和旋转保长性。

不可靠的部分在物理参数，而不在算法。README 里明确写了研究边界： 镜面中心、初始法向、旋转轴不在规格表里，默认值是为了让雅可比满秩而设的 紧凑虚拟光路，不代表厂商内部真实结构。

所以接真机时必须替换这些参数，并用实测标定数据重新训练 —— 这也是为什么代码把 mirrors 和 errors 都设计成可传入的数据类字段。

补偿前后差 4 个数量级，这个结果可信吗？是不是过拟合了？

不是过拟合，原因是问题本身是确定性的且光滑：

① 真机误差是固定的一组常数（create_seeded_real_machine(seed=2026)）， 不是每次随机；② 没有测量噪声；③ 误差随位姿平滑变化。

这种条件下，21 个参数的二阶多项式在 400 个样本上拟合，残差落到 0.002 μm 是合理的。

但这恰恰是它的局限：真实设备有噪声、热漂移、迟滞，残差不可能这么低。 README 里专门写了「模型仅包含确定性误差，仿真残差不能当作设备实际精度」。

为什么补偿矩阵能修好「姿态」误差，而不只是位置？

因为拟合时误差向量的 5 个分量是一起最小二乘的： errors 是 400×5 矩阵，lstsq 同时解 5 列系数。 所以 C 的每一列对应一个误差分量，位置和姿态一起被建模。

再加上 5 个控制量本身就有 5 个自由度（雅可比满秩）， 所以位置和姿态可以被独立地修正到目标值 —— 这也是「满秩」为什么是个硬约束。

改了镜面布局或规格参数，要动哪些地方？

① specifications.py 的 STANDARD_515_NM —— 改光学规格；

② model.py 的 create_default_machine() —— 改镜面中心、法向、旋转轴；

③ 改完立刻跑测试：.\.venv\Scripts\python -m pytest。 重点看 test_jacobian_is_full_rank 和 test_default_profile_matches_515_nm_standard_workspace —— 布局改动最容易破坏满秩和工作域，这两个测试会立刻报出来。

④ 参数变了以后补偿矩阵必须重新标定，旧的不能复用。

为什么 api.py 里 reload=False？改了代码没生效？

main() 里 uvicorn.run(..., reload=False) 是硬编码的， 意味着改了 Python 代码必须重启服务才生效。

但改 static/ 下的前端文件（index.html、app.js） 只需刷新浏览器。

另外补偿模型是进程内全局状态，训练结果不会持久化 —— 重启服务后需要重新训练（页面会自动做，约 10~30 秒）。

本文所有数字均为本机实跑结果，可用 .\.venv\Scripts\python -m pytest 复现测试， 或用页面上的滑块直接观察。
