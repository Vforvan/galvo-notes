## 2. ⭐ sigrok 解码器（最权威）

**位置**：`99-附件与下载/代码/sigrok-xy2-100-decoder/pd.py`

**为什么最重要**：它是**接收端**实现，被 sigrok/PulseView 广泛使用，
经过大量真实设备验证，**正确性最可信**。

### 关键代码解析

```python
# 1) 采样时刻: CLK 上升沿取状态, 下降沿取数据
while True:
    clk, sync, data, stat = self.wait({0: 'e'})    # 等任意边沿
    if clk == 1:                # 上升沿
        stat_value = stat
        bit_es = self.samplenum
        if bit_ss:
            self.process_bit(sync_value, bit_ss, bit_es, bit_value)
    else:                       # 下降沿 → 采样数据 ✅
        bit_value = data
        sync_value = sync
```

```python
# 2) 校验: 对【前 19 位】求偶校验
parity = 0
for ss, es, value in self.bits[:-1]:     # bits[:-1] = 前 19 位
    parity ^= value
par_ss, par_es, par_value = self.bits[19]     # 第 20 位是校验位
parity_even = 1 if (par_value == parity) else 0
```

> [!success] ✅ 这两段代码确认了两件关键事实
> 1. **数据在 CLK 下降沿被采样**
> 2. **偶校验覆盖前 19 位（含控制字）**，不是只覆盖 16 位数据
>
> 详见 [[01-协议篇/02-帧结构详解]] 的校验范围一节。

```python
# 3) 帧类型识别
type_1_value = self.bits[0][2]                              # 第 1 位
type_3_value = (bits[0]<<2) | (bits[1]<<1) | bits[2]        # 前 3 位

if (type_1_value == 1) and (parity_odd == 1):    # 首位 1 + 奇校验 → 18 位
    type = frame_type_18bit_pos
elif (type_3_value == 1):                         # 001 → 16 位
    type = frame_type_16bit_pos
elif (type_3_value == 7) and (parity_even == 1):  # 111 → 命令帧
    type = frame_type_command
```

```python
# 4) 无符号 → 有符号转换 (MSB first 拼接)
if (type == frame_type_16bit_pos):
    count = 15
    for ss, es, value in self.bits[3:19]:      # 第 4~19 位是数据, MSB first
        pos |= value << count
        count -= 1
    pos = pos if pos < 32768 else pos - 65536  # 转成 -32768..32767
```

> [!note] 💡 一个值得注意的警告注释
> ```python
> self.put_ann(..., ['Careful: 18-bit position frames with wrong parity '
>                    'and command frames with wrong parity cannot be identified'])
> ```
> 作者明确指出了协议的一个**固有歧义**：校验错误的 18 位帧无法与校验错误的命令帧区分。
> 这是协议设计上的限制（20 位里没有足够的空间放完整类型标识）。

### 怎么用

1. 装 **PulseView**（sigrok 的 GUI）
2. 接上 ¥20 的 USB 逻辑分析仪，探头接 CLK / SYNC / X（或 Y）
3. 添加解码器 → 选 **XY2-100**
4. 直接看到每帧的位置值和校验状态 ✅

> [!tip] 💡 这是本知识库最实用的一条建议
> **信号线一定要接到逻辑分析仪上**（如果不用 STATUS，接 CLK/SYNC/X 三根就够）。
> XY2-100 的问题几乎都是时序问题，而时序问题**看不见就修不了**。

## 3. ⭐ XY2Galvo（最优雅的实现）

**位置**：`99-附件与下载/代码/XY2Galvo-rp2040/`

| 文件 | 作用 |
|---|---|
| `src/XY2-100.pio` | PIO 汇编，生成 CLK/SYNC/X/Y ⭐ |
| `src/XY2Galvo.h` | 引脚定义、API |
| `src/basic_geometry.h` | 几何图形生成 |
| `src/Queue.h` | 跨核命令队列 |

### 核心设计

```pio
; 时钟与 SYNC 状态机
.program xy2_clock
.side_set 4                              ; clock± sync± 四个引脚

.wrap_target
public start:
    nop         side (SYNC_LOW + CLOCK_HIGH) [1]   ; 第20位: 校验位
    set x, 18   side (SYNC_LOW + CLOCK_LOW)  [1]   ; => 19 次循环
a:  nop         side (SYNC_HIGH + CLOCK_HIGH)[1]   ; 第 1..19 位
    jmp x-- a   side (SYNC_HIGH + CLOCK_LOW) [1]
.wrap
```

**这段代码的注释本身就是规范的正确解读**：
- 第一行明确标注 `; bit 20: parity`，且 SYNC 为 **LOW**
- 循环 **19 次**输出 SYNC **HIGH**
- 结果：**SYNC 高 19 位、校验位为低** ✅ 与规范完全一致

> [!success] 这是独立的第三方验证
> 开发者 Kio! / Mathema GmbH 从零写的实现，独立得出了与规范相同的结论。
> 这比任何二手教程都可信。

### 三个值得学的技巧

**技巧 1：side-set 同时设置相邻引脚**

```pio
.define HIGH 0b01       ; pin N = 1, pin N+1 = 0
.define LOW  0b10       ; pin N = 0, pin N+1 = 1
```

一条 PIO 指令就能同时设置 P 和 N，**保证两者的边沿完全对齐**。
这就是 P/N 必须用相邻 GPIO 的原因。

**技巧 2：用"程序流"跟踪奇偶校验**

PIO 没有 ALU，做不了异或。作者的解法：

```pio
loop_even:                              ; 当前校验状态 = even
    out y, 1
    jmp !y, send_0_even
send_1_even:
    jmp loop_end_odd  side DATA_HIGH    ; 发 1 → 状态翻转到 odd
send_0_even:
    jmp loop_end_even side DATA_LOW     ; 发 0 → 状态保持 even

; 循环结束时, "在哪个分支"就等于校验位应该是什么
loop_end_even:
    jmp next_word  side DATA_HIGH [3]   ; 发 PE = 1
loop_end_odd:
    jmp next_word  side DATA_LOW  [3]   ; 发 PE = 0
```

> [!tip] 💡 教科书级技巧
> 用**代码分支**代替**变量**来保存状态。
> 在只有跳转指令的极简处理器上（PIO 就是），这是唯一可行的办法。

**技巧 3：用第三个状态机仲裁 X/Y 同步**

因为 X 和 Y 的 FIFO 是独立的，写入时刻不同，可能一个空了另一个还有数据。
该实现专门用一个状态机检查 FIFO 状态，并通过同步引脚通知所有数据状态机：

```pio
; "fifo empty: all state machines must not read the fifo but use old data instead"
; "data available: all state machines must read the fifo for new data"
```

> [!important] 这解决了一个致命问题
> 如果 X 用了新数据而 Y 还在用旧数据 → **两轴不同步** → 图形扭曲。
> 见 [[00-入门篇/04-常见误区]] 误区 5。

### 引脚分配

| 信号 | GPIO |
|---|---|
| CLOCK+ / CLOCK− | 8 / 9 |
| SYNC+ / SYNC− | 10 / 11 |
| Y+ / Y− | 12 / 13 |
| X+ / X− | 14 / 15 |
| PIO 同步 | 16 |
| LASER | 22 |

## 4. ⚠️ xy2-100-arduino（最易读，但有 bug）

**位置**：`99-附件与下载/代码/xy2-100-arduino/`

### 值得学的地方

代码极其简洁，**是理解协议流程的最佳入门材料**：

```cpp
void XY2_100::_write(int x, int y) {
  _clock->set(1);
  _syn->set(1);
  // 写 "001" 头部
  _x->set(0); _y->set(0); _clock->set(0); _clock->set(1);   // 0
  _x->set(0); _y->set(0); _clock->set(0); _clock->set(1);   // 0
  _x->set(1); _y->set(1); _clock->set(0); _clock->set(1);   // 1
  // 写 16 位数据 (MSB first)
  for (int i = 0; i < 16; i++) {
    unsigned char b = (x >> (15 - i)) & 1;      // ← 先取 bit15, MSB first ✅
    ...
  }
  // 写校验位
  ...
  _syn->set(0);                                  // ← ⚠️ 时机不对
}
```

✅ **正确的地方**：
- MSB first（`(x >> (15 - i))`）
- 头部 `001`
- X/Y 同时发送
- 差分对互补输出

### ⚠️ 三个真实缺陷

> [!danger] 缺陷 1：校验位算错
> ```cpp
> for (int i = 0; i < 16; i++) {
>   unsigned char current_bit_x = (x >> (15 - i)) & 1;
>   even_parity_bit_x ^= current_bit_x;      // ← 只异或了 16 位数据
> }
> ```
> 规范的偶校验要覆盖**前 19 位（含控制字 `001`）**。
> 因为控制字含 1 个 `1`，**这个实现实际变成了整帧奇校验**。
>
> 📌 这不是我一个人的判断——调研中用**三个独立的接收端解码器**
> （sigrok / danmcb-Saleae / earlynerd-HLA）交叉验证，一致确认应为 19 位。

> [!danger] 缺陷 2：SYNC 时序不对
> ```cpp
> _clock->set(0); _clock->set(1);   // 校验位的时钟
> _syn->set(0);                     // ← 校验位发完之后才拉低
> ```
> SYNC 在**校验位之后**才拉低，意味着 SYNC 高电平覆盖了 **20** 位。
> 规范要求覆盖 **19** 位（校验位期间就该是低）。

> [!danger] 缺陷 3：达不到 2 MHz
> 作者自己在 README 里承认了：
> > "Does this work at the standard rate of 2MHz? **Most likely not**,
> > but an Arduino Nano seems to be able to drive a galvo just fine."

### 🤔 那为什么它"能用"

很多振镜的接收端**容错性比规范宽松**：
- SYNC 相位略有偏差仍在容忍范围内
- 部分振镜**不检查**校验位
- 时钟慢一些无所谓（只要不太慢）

> [!warning] 但这不代表你可以这么写
> 遇到严格按规范实现的振镜（如 SCANLAB 高端型号）就会出问题。
> **学它的思路可以，抄它的代码要改。**

## 5. OPAL（G 代码集成）

**位置**：`99-附件与下载/代码/OPAL-gcode-to-xy2-100/`

**定位**：把 **G 代码解析 → XY2-100 输出**的完整固件。

| 特点 | 说明 |
|---|---|
| 支持振镜 | SinoGalvo SG7110（测试用） |
| 激光控制 | Synrad 48 系列、SSR 控制激光电源 |
| 价值 | 学习"完整系统怎么集成"，而不只是协议层 |

> [!warning] ⚠️ 作者的安全警告
> 作者明确警告：**固件可能随时崩溃，导致振镜与激光处于未知状态**。
> 💡 这也是一个真实教训：**激光设备必须有独立的安全联锁**，
> 不能只依赖软件。

> [!note] 且它也有同样的校验位 bug
> OPAL 与 georgemihaila 版本都只对 16 位数据求校验。
> 这说明这个坑**非常容易踩**——两个独立项目都踩了。
> **你自己实现时务必注意。**
