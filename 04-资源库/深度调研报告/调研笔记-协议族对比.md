## 1.2 已核实的起始事实（标准版 vs Enhanced）

| 项目 | XY2-100 标准版 | XY2-100 Enhanced (-E) | 来源 |
|---|---|---|---|
| 帧长 | **20 bit** | **20 bit** | **(a)** Newson 数据手册；**(a)** E1803D 手册 Appendix B |
| 帧头控制字 | 前 3 bit = `001` | **第 1 bit = `1`** | **(a)** 同上 |
| 位置位宽 | **16 bit（D15..D0）** | **18 bit（D17..D0）** | **(a)** 同上 |
| 校验 | **偶校验 Pe**，占最后 1 bit | **奇校验 Po**，占最后 1 bit | **(a)** 同上 |
| 位序 | 高位先发（bit19 → bit0） | 同 | **(a)** Newson 数据手册信号图 |

一手原文（Newson，**(a)**）：
> "The data of each axis consist of 20-bit words. The first 3 bits are used as a control word (C2-C0). The next 16 bits are data information (D15-D0, offset binary) and the last bit is a parity bit (P, even parity)."
> — https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/171/Documents_5F00_TD_5F00_XY2_2D00_100_5F00_R0703.pdf

一手原文（HALaser E1803D，**(a)**）：
> "In standard 16 bit operating mode first three bits are set to 001, then 16 bit position data followed by a parity bit (even parity) are transmitted… In enhanced XY2-100E 18 bit operating mode first bit is set to 1, then 18 bit position data followed by a parity bit (odd parity) are transmitted"
> — https://halaser.eu/manuals/e1803_manual.pdf

**位图（bit map）表**：

标准 16 bit（**(a)** https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/171/Documents_5F00_TD_5F00_XY2_2D00_100_5F00_R0703.pdf 、https://halaser.eu/manuals/e1803_manual.pdf）

| bit19 | bit18 | bit17 | bit16 … bit1 | bit0 |
|---|---|---|---|---|
| 0 | 0 | 1 | D15 … D0（16 bit 位置，offset binary） | Pe（偶校验） |

| bit19 | bit18 … bit1 | bit0 |
|---|---|---|
| 1 | D17 … D0（18 bit 位置） | Po（奇校验） |

## 1.3 时序、时钟、SYNC

- **(a)** SYNC 高电平持续 19 bit，发送校验位时拉低 —— "The SYNC bit goes high when the first bit can be sent. It remains high for 19 bits and goes low when the parity can be sent." — https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/171/Documents_5F00_TD_5F00_XY2_2D00_100_5F00_R0703.pdf
- **(a)** SYNC 上升沿标记帧开始，下降沿标记当前帧最后一位开始 —— https://www.aaronvose.net/Quantronix_Osprey/xy2_100_specification.pdf
- **(a)** 时钟边沿：**时钟上升沿数据变化，下降沿被振镜采样** —— "When it goes high, the data bit changes. When it goes low, the data bit is sampled by the deflection system." — https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/171/Documents_5F00_TD_5F00_XY2_2D00_100_5F00_R0703.pdf
- **(a)** RAYLASE 对 -E 的描述一致：CLK+ 正沿更新下行数据（X/Y/Z），CLK+ 负沿更新上行反馈数据（X_stat/Y_stat/Z_stat），即**反馈通道比下行通道延迟约半个时钟** —— http://www.alaser.com.tw/db/upload/webdata4/5alaser_201412422541519318.pdf （§3.1）
- **(a)** 建立/保持时间：data-in setup time tDS ≥ **50 ns**；data-in hold time tDH ≥ **100 ns** —— https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/171/Documents_5F00_TD_5F00_XY2_2D00_100_5F00_R0703.pdf

## 1.4 数据编码 —— 三种表述，实质一致 (c)

| 表述 | 来源 |
|---|---|
| "**offset binary**"（偏移二进制） | **(a)** https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/171/Documents_5F00_TD_5F00_XY2_2D00_100_5F00_R0703.pdf |
| "interpreted as **unsigned integer**, D0 = LSB, D15/D17 = MSB" | **(a)** http://www.alaser.com.tw/db/upload/webdata4/5alaser_201412422541519318.pdf （§3.3.1） |
| "**16-bit signed integers**, with 0 being the center" | **(b)** https://sigrok.org/wiki/Protocol_decoder:Xy2-100 |
| 坐标范围 (-res/2) … (res/2)-1，**原点在加工场中心** | **(a)** https://software.raylase.de/rpi/RAYLASE/SPICE3/UsersManual%20v2.3.5/html/9af8557b-2e37-4587-9ea2-c67b1aea40c2.htm |

> **结论**：三者等价 —— 码值 0 对应振镜中心位置，向下/向上对称分布。RAYLASE 称之为 unsigned / offset binary，sigrok 称之为 signed；两者描述的是同一根轴的同一组码，只是"零点"定义表述方式不同（16 bit offset binary 与 16 bit 二进制补码之间只差 MSB 取反）。
> **18 bit 与 16 bit 的换算**（二手实现经验）：16 bit 值左移 2 位得 18 bit 值，再减去 2^17（131072）即得 offset binary 码 —— **(b)** https://blog.csdn.net/weixin_51352668/article/details/161866786

## 1.5 控制字 C2 C1 C0 —— 各编码含义

### 命令方向（控制器 → 振镜）

**已由一手文档明确的**只有以下两组：

| C2 C1 C0 | 含义 | 来源 |
|---|---|---|
| `0 0 1` | **电机位置设定值**（motor setpoint value），后接 16 bit 位置 + 偶校验 | **(a)** https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/171/Documents_5F00_TD_5F00_XY2_2D00_100_5F00_R0703.pdf （原文表格："C2=0, C1=0, C0=1 → data information = motor setpoint value"） |
| 首 bit = `1` | 18 bit Enhanced 位置帧（其后 17 bit 参与构成 D17..D0 的一部分；不是 3 bit 控制字，而是 1 bit 模式标识） | **(a)** https://halaser.eu/manuals/e1803_manual.pdf ；**(a)** https://www.aaronvose.net/Quantronix_Osprey/xy2_100_specification.pdf |

**`000` / `010` / `011` / `100` / `101` / `110` / `111` 在命令方向的含义：未找到公开数据。** 本次检索（英文 + 中文，含 sigrok、Newson、RAYLASE SS-III -E 手册、HALaser E1803D 手册、SCANLAB RTC 资料）均未找到任何一手文档给出这 7 个码值的定义。请勿自行编造。

**最接近的间接证据（RAYLASE XY2-100-E 命令帧，但图示位域存在歧义）**：RAYLASE SS-III -E 手册 §3.3.1 声明命令方向存在**三种帧型**，并说明命令帧承载"**8 bit 命令字节 + 8 bit 参数字节**"，且"**18 bit 目标位置帧与命令帧的区分靠不同的奇偶校验**"：

> "Command frame (according XY2-100-E specification 8 bit command and 8 bit parameter)… The distinction between 18Bit target position frame and command frame occur by the different parity. This can cause that the deflection unit possibly cannot identify parity error any longer."
> — **(a)** http://www.alaser.com.tw/db/upload/webdata4/5alaser_201412422541519318.pdf

因为 3 bit 控制字 + 8 bit 命令 + 8 bit 参数 + 1 bit 校验 = **20 bit**，与帧长自洽，可以推断 -E 的命令帧正是把 16 bit 位置字段重解释为"命令字节 + 参数字节"。但该手册的位域示意图经 150/200/300 dpi 渲染后仍无法可靠分辨各格标注，**故本笔记不给出 -E 命令帧控制字的具体码值**。

**同类现象**：sigrok 解码器明确指出 18 bit 模式与 -E 命令模式无法区分：

> "the 18-bit mode is in part indicated by an inverted parity bit (odd parity) while the command mode available in the -E variants uses the default even parity. This means that it's impossible to determine when a command mode transmission was corrupted as it'll just look like an 18-bit position transmission and vice versa."
> — **(b)** https://sigrok.org/wiki/Protocol_decoder:Xy2-100

> 注：该 sigrok 说法与 RAYLASE 的说法方向相反（RAYLASE 说 18 bit 用奇校验、命令帧用偶校验；sigrok 说 18 bit 用**反转的**校验位）。两者都指出"18 bit 位置帧"与"命令帧"只能靠校验位极性区分，且该机制不可靠。**(c)**

### 返回方向（振镜 → 控制器）：3 bit 状态字

**这是本次调研最明确的发现。** HALaser E1803D 官方手册 API 附录给出了返回帧前 3 bit 的**识别位**定义，并区分 2D 头与 3D 头：

| 头类型 | bit19 / C2 | bit18 / C1 | bit17 / C0 | 识别码 |
|---|---|---|---|---|
| **2D 扫描头** | 0 | 1 | 1 | `0 1 1` |
| **3D 扫描头** | 0 | 0 | 1 | `0 0 1` |

- **(a)** https://halaser.eu/manuals/e1803_manual.pdf （`E180X_get_head_state()` 说明表，文档第 112 页）
- 原文：`Bit 19 / C2 … 0 (Identification bit)`、`Bit 18 / C1 … 1 / 0`、`Bit 17 / C0 … 1 / 1`；并注明"当扫描头不提供此类信息、返回无效数据或使用私有格式时，函数返回 0xFFFFFFFF"。

**这与 RAYLASE 的描述可以互相印证但位划分不同 (c)** —— RAYLASE 把返回帧头描述为 **4 bit**：

| 返回帧型 | 帧头 | 后续 | 来源 |
|---|---|---|---|
| 16 bit 向下兼容型 | `0 0 1 1` | D15..D0（16 bit） | **(a)** http://www.alaser.com.tw/db/upload/webdata4/5alaser_201412422541519318.pdf （Diagram 4） |
| 16 bit 标准型 | `0 0 0 1` | D15..D0（16 bit） | **(a)** 同上 |
| 18 bit 型 | `0 1` | D17..D0（18 bit） | **(a)** 同上 |

> **(c) 冲突点**：HALaser 为"3 bit 识别位 + 16 bit 状态 + 1 bit 校验"；RAYLASE 为"4 bit 帧头 + 16 bit 数据"（无校验位）。两者都能拼满 20 bit，但位划分不兼容。这是**厂商实现差异**，不是文档错误。

## 1.6 返回/状态通道的内容 —— 三种互不兼容的实现 (c)

sigrok 官方解码器文档直言该通道无法统一解码：

> "The status or feedback signal is unfortunately not straightforward to decode. The mean reason is that there are at least 3 different variants: backwards-compatible 16 bit, standard 16 bit and 18 bit. They can't be distinguished from another and the user would have to specify which to expect."
> — **(b)** https://sigrok.org/wiki/Protocol_decoder:Xy2-100

### 实现 1：单根 STATUS 位（Newson，最简）**(a)**

Newson 的 XY2-100 数据手册中，返回通道**不是 20 bit 帧，而是一根独立的 STATUS 信号线**，且**不与 SENDCK 同步**：

> "The status bit is sent by the deflection system, it is not synchronised with the SENDCK input. The STATUS bit is '0' when: the X axis position < maximum position error and the Y axis position < maximum position error and the effective rotor X current < warning level and the effective rotor Y current < warning level and the digital regulator runs. The STATUS bit is '1' when at least one of these conditions is false."
> — **(a)** https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/171/Documents_5F00_TD_5F00_XY2_2D00_100_5F00_R0703.pdf
> 该文档引脚表中 STATUS 定义为 `IO6-/IO6+`（pin 6/19），方向为 Output。

### 实现 2：16 bit 状态字（8 bit 重复两次）**(a)**

RAYLASE SS-III 的 "Status word 0x00" 说明：

> "Corresponds to the status word of the standard XY2-100 (without -E). The status word consists of 8 Bit which are repeated in upper and lower Byte."
> — **(a)** http://www.alaser.com.tw/db/upload/webdata4/5alaser_201412422541519318.pdf （§4.3.1.1）

**完整位定义（低 8 bit；高 8 bit 为同样内容重复）**(a)：

| bit | 含义（=1 时） |
|---|---|
| bit15 / bit7 | axis at work（=0 表示 failure） |
| bit14 / bit6 | galvo 温度正常（=0 表示温度故障；SS-III 恒为 OK，因未测该温度） |
| bit13 / bit5 | Z 轴位置在 tracking failure window 内（SS-III **未实现，恒为 1**） |
| bit12 / bit4 | X 轴（小镜）位置在 tracking error window 内（窗口可由命令 `SetPosAcknowledgeLevel (0x15)` 配置） |
| bit11 / bit3 | Y 轴（大镜）位置在 tracking failure window 内 |
| bit10 / bit2 | 自动校准传感器未激活（无自动校准时恒为 1） |
| bit9 / bit1 | **恒为 0** |
| bit8 / bit0 | **恒为 1** |

来源：**(a)** http://www.alaser.com.tw/db/upload/webdata4/5alaser_201412422541519318.pdf （§4.3.1.1，文档第 20 页）

### 官方原文结构（逐条照录）**(a)**

> **SL2-100 protocol:**
> • Is **bidirectional**
> • Is **serial**
> • Requires **2 separate channels**
>   – **Forward Channel** (designated here from the perspective of the RTC board)
>     • 1 channel for the direction **RTC board → iDRIVE scan system**
>     • In Figure 15: cable wire from pin 05 → pin 01 (blue) and cable wire from pin 09 → pin 06
>   – **Return Channel**
>     • 1 channel for the direction **iDRIVE scan system → RTC board**
>     • In Figure 15: cable wire from pin 05 → pin 01 (red) and cable wire from pin 09 → pin 06
> • Data in Forward Channel and Return Channel are transported in **blocks** ("SL2-100 block", "transmission block")
> • With SL2-100 protocol, Forward Channel and the Return Channel are **completely independent** of each other
> • Accordingly, both have their own SL2-100 blocks (= SL2-100 Forward Channel block and SL2-100 Return Channel block)
> • A **block start in one direction does not automatically mean a block start in the other direction**
> • The following applies:
>   – **1 block consists of 192 frames = "block length"**
>   – **Each block starts with a preamble (generated by the RTC board)**
>   – **1 frame consists of 2 sub-frames**
>   – **1 frame is transmitted in 10 µs**
>   – **1 sub-frame contains**
>     • **20 bits of payload** (control values or status values)
>     • **12 bits of further information** (for example, for synchronization)
>
> — RTC6 Manual, Doc. Rev. 1.1.4 en-US, p.1213–1214，https://raw.githubusercontent.com/labspiral/sirius3/main/doc/SCANLAB/RTC6_Manual.en.pdf

### 结构分解表

| 层级 | 组成 | 数值 |
|---|---|---|
| 1 Block | 帧 | **192 帧** |
| — | 起始 | **Preamble**（由 RTC 板产生） |
| 1 Frame | 子帧 | **2 个子帧**（X 轴 + Y 轴） |
| — | 时间 | **10 µs** |
| 1 Sub-frame | 载荷 | **20 bit**（控制值或状态值） |
| — | 附加信息 | **12 bit**（例如用于同步） |
| Sub-frame 内部位域 | Bit 0…Bit 19 | **Data**（官方原文，见 `set_trigger` Signal1 = 63 说明） |
| — | **Bit 20** | **Synchronization information**（官方原文） |

### 子帧位布局（第三方逆向，与官方 20+12 的计数**精确吻合**）**(b)**

来源：https://blog.csdn.net/ttstststtttt/article/details/145651470 ；https://blog.csdn.net/weixin_51352668/article/details/161866786

| 序号 | 字段 | 位宽 | 归属 |
|---|---|---|---|
| 1 | 帧起始位 | 1 bit | ← 官方"12 bit 附加信息" |
| 2 | **模式选择位** | **6 bit** | ← 官方"12 bit 附加信息" |
| 3 | 轴数据位（**低位先发 LSB → MSB**，**有符号**） | **20 bit** | ← 官方"20 bit payload" |
| 4 | 控制位（"就是 XY2-100 协议里的控制位，一样的"） | **3 bit** | ← 官方"12 bit 附加信息" |
| 5 | 校验位（**奇校验**，覆盖 模式 + 数据 + 控制位） | 1 bit | ← 官方"12 bit 附加信息" |
| 6 | 停止位 | 1 bit | ← 官方"12 bit 附加信息" |
| **合计** | | **32 bit** | 1+6+3+1+1 = **12 bit** ✓ |

> **交叉验证成立**：逆向出的 12 bit 附加信息（1 起始 + 6 模式 + 3 控制 + 1 校验 + 1 停止）与官方"12 bits of further information"**数量完全一致**。1 帧 = 2 子帧 = 32 + 32 = **64 bit**，与论坛实测"一帧 128 bit / 10 µs"（64 × 2 差分曼彻斯特码元）也**完全一致**。
> Y 轴子帧结构相同；**模式选择字段的第 1 位用于区分轴：0 = X 轴，1 = Y 轴** —— **(b)** https://blog.csdn.net/weixin_51352668/article/details/161866786

### 关于"26 bit"说法的最终核查 (c)

**"26 bit"不是 SL2-100 的帧长。** 出现 26 bit 的官方语境有两个，均与 SL2-100 帧长无关：
1. HALaser 控制器的**内部运算分辨率** 26 bit："26 bit internal resolution (for better accuracy also with 16 bit or 18 bit hardware output)" —— **(a)** https://halaser.eu/manuals/e1803_manual.pdf
2. **XY3-100 的位置分辨率上限** 26 bit（LasIA 官方规范）—— 见 §3

> 另有一种合理解释：6 bit 模式 + 20 bit 数据 = **26 bit 载荷字段**（不含成帧开销）。但**没有官方文档这样表述**，故仅作备注。

## 2.4 编码与位速率

### 编码：差分曼彻斯特（Differential Manchester），自同步

- **(b)** 逆向实测：`32bit + 32bit = 64bit`；"使用的是**差分曼彻斯特编码**方式"；20 bit 数据在物理层占 **40 个差分曼彻斯特码元**（1 bit : 2 cell）—— https://blog.csdn.net/ttstststtttt/article/details/145651470 ；https://blog.csdn.net/weixin_51352668/article/details/161866786
- **(b)** 论坛实测（RTC6 抓波形）："one data-frame is **128 bits length and 10 µs time cost**"，编码方式像 Manchester —— https://www.photonlexicon.com/forums/showthread.php/28608-SL2-100-Protocol-for-scanner
- **(a) 官方间接印证**：SCANLAB 从未写出 "Manchester" 字样，但 RTC6 手册的错误位定义**只能由自同步编码产生**（见下）。这构成强力旁证。

### 官方定义的 SL2-100 返回通道错误位（一手）**(a)**

来源：RTC6 Manual Doc. Rev. 1.1.4 en-US，`Ctrl Command get_startstop_info` 结果位（文档第 498 页起）
https://raw.githubusercontent.com/labspiral/sirius3/main/doc/SCANLAB/RTC6_Manual.en.pdf

| 位 | 含义（=1 时置位） |
|---|---|
| Bit #16 | Incorrect **number of frames** within a data block |
| Bit #17 | Incorrect **pulse length** of signal received from scan system, maybe no scan system is connected |
| Bit #18 | **Preamble** sequence incorrect |
| Bit #19 | **Bit count within a subframe** incorrect |
| Bit #20 | **Parity error** when reading data received from scan system |

### 帧结构（官方原文，**(a)**）

- **(a)** 传输方式："16..26 bit position data are transferred from scanner controller data to scanner card using lines SYNC+-, CLK+-, X+-, Y+- and optional Z+-, U+- and W+- using a **fixed frame-length (10 usec typically for 100 ks/sec)** but a **variable frame-size** regarding the amount of contained data bits"
- **(a)** 总线性质：**SPI-like**。"The beginning of a frame is marked by the **falling edge at the SYNC-channel (CS)**. Whenever data at X, Y, Z, U and W channel (SDI) are valid, this is signalled by a **falling edge on the CLK-channel (SCK)**."
- **(a)** 帧长由**第 1 个 bit** 决定："The first bit (n, 31 or 23) signalises the length of the whole frame. When it is **0**, the frame has a total length of **24 bits with a payload of 22 bits**. When it is **1**, it has a length of **32 bits with a payload of 30 bits**."
- **(a)** 第 2 个 bit 决定帧类型：**1 = 位置帧，0 = 命令帧**

**两种位置帧（官方，**(a)**）**：

| 帧型 | 帧头 | 位置数据 | 校验 | 100 ks/s 时钟 | 最大位置位宽 |
|---|---|---|---|---|---|
| **24 bit 位置帧** | `0 1` | **D19..D0** | **P1 P0** | **2.4 MHz**（10 µs） | **20 bit** |
| **32 bit 位置帧（推荐）** | `1 1` | **D25..D0** | **P3 P2 P1 P0** | **3.2 MHz**（10 µs） | **26 bit** |

- **(a)** 200 ks/s 高速档：24 bit 帧 → 5 µs / **4.8 MHz**；32 bit 帧 → 5 µs / **6.4 MHz**（"Depending on the hardware capabilities on both ends, higher transmission rates are allowed too"）
- **(a)** 校验算法（24 bit）："count the number of bits set to 1 in D19..D0 (bits 21..2)"，取 `& 0x03` 写入 P1P0
- **(a)** 校验算法（32 bit）："count the number of bits set to 1 in D25..D0 (bits 29..4)"，取 `& 0x0F`，按 **P3 (0x08) / P2 (0x04) / P1 (0x02) / P0 (0x01)** 掩码写入
- **(a)** 低位补齐规则："can use the full available amount of 20 bits or less. In case of less, the **lower, minor bits have to be set to 0**"
- **(a)** 26 bit 帧的用途说明："The 26 bit accuracy not necessarily needs to be used for outputting them at the scanhead. Assumed the output … higher resolution, this position frame can be used to transmit the full resolution intermediate data to the … provide better accuracy results also in case the real output resolution is smaller than 26 bits."

**两种命令帧（官方，**(a)**）**：

| 帧型 | 帧头 | 命令数据 | 校验 |
|---|---|---|---|
| 24 bit 命令帧 | `0 0` | D19..D0 | P1 P0 |
| 32 bit 命令帧 | `1 0` + bits 24..29 未用（须置 0） | D19..D0 | P3 P2 P1 P0 |

- **(a)** 命令只在下行 X 通道（及可选的 Y/Z/U/W 并行通道）发出："a data sink is free to ignore control commands on all other channels except X"
- **(a)** 命令全部可选："The control commands itself all are optional, a data sink has to react on them only when it supports the related function. All other or unknown control commands can be ignored."

> **此前"24 bit vs 32 bit"的冲突已解决**：**两种帧型在官方规范中同时存在**。HALscan X20 手册说的 "24 bit XY3-100 raw frames with included 20 bit position data" 对应 **24 bit 位置帧**；Scribd 摘要中的 "3.2 MHz / 10 µs" 对应 **32 bit 位置帧**。两者都正确。

### XY3-100 回传通道（最大架构差异，**(a)**）

- **(a)** "The backchannel via the BACK–lines (F+/F+) is **completely independent from the CLK line** of the position data channels. It is an **RS485 serial interface** with a **default transmission rate of 115200 bps, 8 data bits, 1 stop bit and no parity**"
- **(a)** 包结构固定 4 段：

| Head | Type | Length | Payload |
|---|---|---|---|
| 8 bit，**恒为 0x48** | 8 bit 包类型 | 8 bit，后续数据长度 | 长度由上一字节指定 |

- **(a)** 同步包：`0x48 0x41 0x00`（Head + Type=0x41 + Length=0）。接收方在数据流中找到 `0x48 0x41 0x00 0x48` 即可判定重新同步；`0x48` 未出现在上一包末尾或包长非法时须判定失步并丢弃数据直到重新同步。发送方应**不时发送同步包**给接收方重同步机会。

> **三家独立一手文档（RAYLASE / SCANLAB / Newson）一致确认 XY2-100 是 `1/14 = CLK、2/15 = SYNC`；而 LasIA 官方 XY3-100 规范是 `1/14 = SYNC、2/15 = CLK`。因此规范中"Same pinout as XY2-100(E)"只在数据线上成立，CLK/SYNC 是交换的。**
> **同卡双模式交叉验证 (a)**：HALaser E1803D 在 XY2-100 模式下 26-pin 为 `1/2 = CLK、3/4 = SYNC`，切到 XY3-100 模式后变为 `1/2 = A = SYNC、3/4 = B = CLK` —— 同卡两种模式的引脚功能确实互换。见 https://halaser.eu/manuals/e1803_manual.pdf
> **X/Y/Z 数据线（3/16、4/17、5/18）两协议一致。**

### 另一处陷阱：X/Y 轴定义厂商相反 (a)

Some other producers define the axis which is first hit by the laser as Y-Axis. Comparing the pinning of a RAYLASE head with those of other producers it can therefore be noticed that the **pins of the X and Y channels are swapped**."

# 4. RTC / SP-ICE 控制卡 —— 概念澄清

## 4.1 核心结论：RTC 是"PC 主机接口型控制卡"，不是振镜侧串行协议

SCANLAB 官方 RTC 合集手册的 Overview 对比表把接口**明确拆成两行**：`PC interface` 与 `Scan head interface`——证明这是同一块卡的两个不同侧面：

- **(a)** https://www.scanlab.de/sites/default/files/2022-04/13_RTC_Combination.pdf

```
上位机 PC
  │  PCI / PCIe / Gigabit Ethernet / USB 1.1        ← RTC 的「主机侧」接口
  ▼
RTC4 / RTC5 / RTC6 控制卡（板载 DSP + 列表缓冲 + 校正表 + 激光时序）
  │  XY2-100 (16-bit)  或  SL2-100 (20-bit)           ← RTC 的「振镜侧」接口
  ▼
振镜扫描头 Scan Head (galvo)
  └─ 激光控制：15-pin D-SUB（RTC5/RTC6）或 9-pin D-SUB（RTC4）
```

一手原文：
> "Control boards of the RTC family enable the intelligent and flexible control of scan systems, lasers and peripheral devices in real time. Thanks to the **PCI Express or Ethernet interfaces**, they can be integrated quickly and flexibly."
> — **(a)** https://www.scanlab.de/en/products/control-electronics/rtc-control-boards
> "It is available as a **PC interface board**, or as a PCI-Express board."
> — **(a)** https://www.scanlab.de/sites/default/files/2020-08/13_RTC5_control%20boards.pdf

> **补充事实 (a)**：RTC 卡的模拟输出**只用于控制激光功率，不用于驱动振镜**。振镜侧始终是数字串行协议（XY2-100 或 SL2-100）。见 https://www.scanlab.de/sites/default/files/2020-08/12_RTC6%20control%20boards.pdf （"12-bit analog output (0...10 V)"列在 Laser Control 之下）。

## 5.2 标度因子（scale factor）—— **已找到多组一手数值，且存在 2 倍陷阱**

### ⚠️ 首先必须区分"机械度"与"光学度"

## 5.4 为什么数字接口取代了模拟接口

- **(b)** 中文技术文章的直接表述（XY2-100 与 SL2-100 的共同目标）：
  > "XY2-100 与 SL2-100 均为「振镜控制卡→振镜」的数字通信协议…**替代传统模拟信号（±10V）传输，解决模拟信号易受干扰、传输距离短、精度不足的痛点**"
  > — https://blog.csdn.net/fq1986614/article/details/159765686
- **(b)** 模拟接口的三个结构性短板（HALaser 对比表）：无纠错、无反馈通道、依赖收发双方电压范围一致 —— https://halaser.systems/compare.php
- **(a)** 长距离传输的官方旁证：SCANLAB 在 SL2-100 连接器上专门提供 **+3.3 V 给 POF（聚合物光纤）转换器**做光传输，官方引脚文档原文："The 3.3 V voltage is supplied for SCANLAB's POF converter for optical data transmission" —— https://www.scanlab.de/sites/default/files/2020-09/pin-out-intelliSCAN.pdf
- **(a)** 微加工场景的分辨率驱动力："The widely used XY2-100 protocol with only 16-bit positioning resolution is often no longer adequate for micro-machining. Here, the 20-bit SL2-100 protocol … is a necessary upgrade." —— https://www.scanlab.de/en/technologies/micromachining
- **(b)** 论坛实测反馈："the SL2-100 protocol has **higher resolution and is more reliable than the XY2-100 protocol when using long distance transmission**" —— https://www.photonlexicon.com/forums/showthread.php/28608-SL2-100-Protocol-for-scanner

> **未找到公开数据**：厂商 app note 层面逐条列举"数字化取代模拟"原因的官方文件（本次未检索到 SCANLAB / RAYLASE / Novanta 的此类专门文档）。

# 9. 给工程实现的关键提示（基于以上来源）

1. **标准 XY2-100 最稳的落地参数**：20 bit 帧、`001` + 16 bit offset binary + 偶校验、位时钟 2 MHz、帧周期 10 µs、SYNC 高 19 bit、时钟**下降沿**采样（上升沿变数据）。**(a)** Newson 数据手册 / LasIA LIA202001
2. **18 bit 不要和命令帧混用同一校验极性方案**：18 bit 与 -E 命令帧只能靠校验位极性区分，本身不可靠。**(a)** RAYLASE + **(b)** sigrok
3. **返回/状态通道必须按具体扫描头型号实现**：至少 4 种公开且互不兼容的格式（单 bit STATUS / 8-bit 重复两遍的 16 bit 状态字 / 带 3 bit 识别位的 20 bit 帧 / 20 bit BACK 帧）。**先要手册，再写代码。**
4. **SL2-100 的官方结构已可获得**（不再是"完全拿不到"）：SCANLAB RTC6 手册附录 F 给出 **1 block = 192 帧 + preamble；1 帧 = 2 子帧 = 64 bit，10 µs；1 子帧 = 20 bit 载荷 + 12 bit 附加信息**。但**完整位域定义（6 bit 模式码表、校验算法）官方仍未公开**，需逆向或采购官方转换器（9-pin SL2-100 → 25-pin XY2-100，引脚文档见 §8.2 #31）。
5. **⚠️ 最需要警惕的工程陷阱：XY2-100 与 XY3-100 在同一条 DB25 上 CLK/SYNC 互换。**
   - **XY3-100（LasIA 官方）**：`1/14 = SYNC (A)`，`2/15 = CLK (B)`
   - **XY2-100（RAYLASE / SCANLAB / Newson 三家一手一致）**：`1/14 = CLK`，`2/15 = SYNC`
   - 数据线 X/Y/Z（3/16、4/17、5/18）两协议一致。规范中"Same pinout as XY2-100(E)"**只在数据线上成立**。
   - 设计兼容两种协议的控制器/转接板时，**CLK 与 SYNC 必须可交换（跳线或固件处理）**。
6. **⚠️ 第二陷阱：X/Y 轴定义厂商相反。** RAYLASE 定义"激光先打到的镜子"为 **X**（小镜），部分厂商定义为 **Y**，因此 X/Y 通道引脚互换。跨厂商替换扫描头时必须核对。
7. **⚠️ 第三陷阱：模拟接口的"机械度 vs 光学度"差 2 倍。** ±10 V 的满量程角度在 0.5 V/机械度 档下是 ±40° 光学，在 1.0 V/机械度 档下才是 ±20° 光学。**不要跨厂商套用 V/° 数值。**
8. **三轴升级路径**：
   - XY2-100 三轴 = 加 Z 差分对（**引脚兼容**，Z 在 pin 5/18）
   - **XY3-100 = 引脚兼容 XY2-100、固件升级可得、开放标准（LasIA）、最多 5 轴（X/Y/Z/U/W）、16..26 bit、异步 RS485 回传。是三者中唯一"开放且文档完善"的。**
   - SL2-100 每连接器限 2 轴，3 轴需两根电缆；RAYLASE RL3-100 单连接器可到 6 轴（私有）
9. **不要把 RTC / SP-ICE 当成振镜协议**——它们是 PC 侧控制卡（PCI/PCIe/以太网/USB）。振镜侧协议仍是 XY2-100 / SL2-100 / RL3-100。
   - **RTC 卡上的模拟输出只用于激光功率，不用于驱动振镜**。
   - RTC5/RTC6 驱动 XY2-100 扫描头**必须加装可选的 XY2-100 Converter**。
10. **模拟接口没有统一协议规范可循**：只需确认电压范围（±5 V / ±10 V / 厂商特定 ±4.8 V）、中心零点、标度因子与输入阻抗。**分辨率由电源噪声决定，不是由 DAC 位数决定**——想要高分辨率，先解决供电质量。
11. **SP-ICE 是 RAYLASE 的产品，与 SCANLAB 无关**。**syncAXIS 是 SCANLAB 的软件**（需 RTC6 PCIe + "syncA" 选件 + ACS SLEC FPGA），不是控制卡。
12. **XY3-100 是唯一公开、免费、文档完整的现代化选项**。若项目需要 3 轴以上、>20 bit 分辨率或异步状态回传，XY3-100 是首选；其规范（LIA202307 + `xy3_100.h`）可自由用于扫描头与控制器。
