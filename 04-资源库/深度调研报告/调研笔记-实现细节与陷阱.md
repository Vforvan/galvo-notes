## 0. 核心结论速览（16 条）

1. **XY2-100 是"时钟速率不敏感"协议**：帧边界由 SYNC 上升沿界定，不由固定时钟数界定。所以纯软件位操作（Arduino Nano）也能驱动振镜，只是刷新率下降。【A/B，§4.5】
2. **奇偶校验的定义存在真实分歧 —— 本报告最重要的发现之一**：4 个独立参考解码器/实现一致采用 `P = XOR(C2,C1,C0,D15…D0)`（对整个 20 bit 字偶校验）；但有 2 个流传很广的开源实现只对 16 bit 数据位做 XOR，结果等价于**对整个 20 bit 字做奇校验**，与 16 bit 规范相反。厂商文档**从未写明统计范围**。【推导 + A，§1.3】
3. **18 bit 模式与命令帧不可区分** —— SIGROK 官方解码器与 RAYLASE 官方文档**双方都明确承认**这个协议缺陷：损坏的命令帧会被误判为合法的 18 bit 位置帧。【A，§1.4】
4. **振镜内部对 100 kHz 指令流做线性插值**：RAYLASE SS-III 默认插值时间 **120 µs**（可设 0–254 µs，步进 2 µs）。插值把离散点流平滑成连续轨迹，**代价是增加一个插值时间的附加延迟**。【A，§4.6、§7.6】
5. **找到了 RAYLASE 官方的数字振镜"传递延迟"精确公式**：`TD_TX = T_K(13 µs) + T_C(20 µs) + T_Int`；`T_Int=0` 时 `TD_TX = 14 µs`；回读方向 `TD_RX = 36 µs`。官方明确要求**开光/关光延时必须补偿"传递延迟 + 跟踪误差"之和**。【A，§6.2】
6. **延迟链量级**：TX(≈53 µs) + 跟踪误差(80–320 µs) ≈ **133–373 µs**，与论文实测的开光 168–173 µs / 关光 450–460 µs 自洽。【A + B，§6.2、§6.5】
7. **XY2-100 的物理层是 RS-422 类差分，不是 LVDS**。最硬证据：RAYLASE 官方直接推荐 RS-422 器件对——驱动 `UA9638CD`，接收 `MAX3096`/`UA9637`，备选 `AM26LV32`；且明确"**without galvanic isolation**"（无电气隔离）。【A，§5.1】
8. **实测到两个真实开源设计的完整 BOM**：`hyperchao0/qspi4xy2-100` 用 **AM26LS31CD**（唯一 IC，**无端接电阻**）；`leswright1977/OPAL_PCB` 用 **SN75174N + CD74HC4050E**（3.3→5 V 电平抬升，**同样无端接**）。任务清单里点名的 LVDS 器件（SN65LVDS / DS90LV）与其他候选**均未找到任何真实振镜设计使用实例**。【A，§5.1】
9. **3.3 V 互补双 GPIO 伪差分可在短线下直连振镜**（Teensy 库作者一手陈述），"For reliable purpose the usage of RS485 drivers with galvanic isolation is strongly recommended"。【A，§5.2】
10. **时钟/同步信号出错时振镜会置故障并关闭输出级**：SS-III 面板 LED "PX/PY 常亮表示 XY2-100 接口的 clock 或 sync 信号出错"，轴故障时 "the output stage of the axis is deactivated"。【A，§4.5】
11. **"~0.15 mrad 分辨率"是误传 —— 溯源成功**：RAYLASE SUPERSCAN IIE 手册中相邻两行分别是 `Resolution XY2-100 16-Bit = 12 µrad` 与 `Long-term drift 8h without water temperature = < 150 µrad`。**150 µrad 就是 0.15 mrad，是 8 小时长期漂移，不是分辨率。** 真实 16-bit 分辨率 **11–12 µrad**，精细约 12–13 倍。用 4 组官方数据核算全部吻合。【A + C，§7.4】
12. **SCANLAB 明确限定：在 XY2-100 接口下定位分辨率就是 16 bit（≈11 µrad）**，优于 16 bit "**only together with SL2-100 interface**"。【A，§7.4】
13. **机械角 vs 光学角标注方式在各厂商间不同，混用会差 2 倍**。RAYLASE "±0.393 rad … All angles optical"；SCANLAB "±0.35 rad (optical)"；Sino-Galvo/JHC "**Mechanical** Scan Angle ±11°"。RAYLASE §2.1.2 还明确说**厂商间 X/Y 引脚是互换的**。【A，§7.7】
14. **机械角 ±11° + 16 bit ⇒ LSB ≈ 11.7 µrad 光学 / 5.9 µrad 机械**（【推导】自 Sino-Galvo 一手量程数据），与 RAYLASE 的 6/12 µrad 一致。
15. **厂商一律不给"带宽 Hz"指标**，只给时域指标（阶跃响应、跟踪误差时间、加速度时间）。小信号阶跃 0.19–0.80 ms，大信号阶跃 0.63–4.50 ms。【A，§7.5】
16. **行业趋势：XY2-100 正被更高分辨率/更高时钟的协议替代**。SCANLAB RTC6 原生用 SL2-100，控 XY2-100 需"**optional converter**"；RAYLASE 主推 XY2-100-E（18 bit）与 RL3-100（20 bit）。**新设计不应把 16 bit/2 MHz 硬编码**。【A，§10】

### 1.2 时钟与同步时序

**【A｜一手】** 原文（Ray-motion 与 Newson rhothor X7 逐字一致）：

> **SYNC**：The SYNC bit goes high when the first bit can be sent. **It remains high for 19 bits and goes low when the parity can be sent.**
> **CLOCK**：The clock signal runs at a frequency of 2 MHz. **When it goes high, the data bit changes. When it goes low, the data bit is sampled by the deflection system.**

| 参数 | 名称 | Min | Typ | Max | 单位 |
|---|---|---|---|---|---|
| data-in setup time | tDS | **50** | — | — | ns |
| data-in hold time | tDH | **100** | — | — | ns |

**【A｜一手】RAYLASE SS-III §3.1 补充了方向相反的说明（用于回读通道）**：

> A frame consists of 20 Bits. **The last bit of a frame is shown by a '0' on the SYNC line pair (The SYNC line pair serves as latch signal).**
> During the **positive edge** of the CLK+ line, data changes on the X-, Y- and Z-line pairs **toward** deflection unit.
> During the **negative edge** of the CLK+ line, data changes on the X_stat-, Y_stat- and Z_stat-line pairs **from** the deflection unit. This means that **the feed-back channels are mainly delayed by half clock time** compared to the channel toward deflection unit.

> **【推导】工程含义**：去程数据在 CLK **上升沿**变化、振镜在**下降沿**采样；回程（STATUS）数据在 CLK **下降沿**变化、控制卡须在**上升沿**采样（与发送侧相反）。

**【A｜一手】位速率与帧率的关系**：
> "It is a serial interface using **20-bit words**, sent with a speed of **2 Mbit/s** or **100 kwords/s**."（Ray-motion / Newson）
> "In XY2-100 and XY2-100E mode one frame with 20 bits has a length of **10 usec** which is similar to **100 kHz** output clock."（HALaser E1803D Appendix B）

→ **100 kHz = 2 MHz ÷ 20 bit**，是位流的自然结果，不是为机械带宽设计的。

### 1.3 奇偶校验：**范围歧义（重点陷阱）**

**【A｜一手】** 所有厂商文档只写 "even parity"，**没有任何一份原文写明 XOR 的统计范围**：

> "The next 16 bits are data information (D15-D0, offset binary) and the last bit is a parity bit (P, even parity)." — Ray-motion / Newson
> "Pe = Parity Even / Po = Parity Odd" — RAYLASE SS-III §3.3.1 Diagram 3

**【A｜一手】5 个独立参考实现/解码器一致采用 `P = XOR(C2,C1,C0,D15…D0)`（对整个 20 bit 字偶校验）**：

| 来源 | 代码要点 | URL |
|---|---|---|
| sigrok 官方解码器 | `parity = 0; for ss, es, value in self.bits[:-1]: parity ^= value` → 对 bit0..bit18（含 C2C1C0）求 XOR；`if par_value == parity: parity_even = 1` | [pd.py](https://raw.githubusercontent.com/sigrokproject/libsigrokdecode/master/decoders/xy2-100/pd.py) |
| Saleae 分析仪 `danmcb/Saleae-XY2-100` | 对 C2/C1/C0 与 16 个数据位累加 1 的个数；`x_parity_ok = ((mX bit == HIGH) == (x_par_ctr & 1))` | [repo](https://github.com/danmcb/Saleae-XY2-100) |
| Saleae HLA `earlynerd/XY2-100_HLA` | `bits_for_parity_check = data_word >> 1; expected_parity = 1 if (num_set_bits % 2 != 0) else 0  # Even parity` | [repo](https://github.com/earlynerd/XY2-100_HLA) |
| Teensy DMA `Tuet/XY2_100` | `Ch1 = ((X << 1) \| 0x20000) & 0x3fffe;` 然后统计 bit0..bit19（含 bit17 = C0 = 1） | [repo](https://github.com/Tuet/XY2_100) |
| STM32 QSPI `hyperchao0/qspi4xy2-100` | `bool xp = 1, yp = 1, zp = 1;` 以 1 初始化（C0=1 贡献一个 1），随后每个数据位翻转 | [repo](https://github.com/hyperchao0/qspi4xy2-100) |

**【推导】另有 2 个流传很广的实现只对 16 bit 数据位求 XOR**：

`georgemihaila/xy2-100`（Arduino/ESP）：
```cpp
  unsigned char even_parity_bit_x = 0;
  for (int i = 0; i < 16; i++) {
    unsigned char current_bit_x = (x >> (15 - i)) & 1;
    _x->set(current_bit_x);
    _clock->set(0); _clock->set(1);
    even_parity_bit_x ^= current_bit_x;      // 只累加 16 个数据位
  }
  _x->set(even_parity_bit_x);
```
`NOBIC-NTU/MiniGalvoControl` 与 `opengalvo/OPAL`（同一份代码）：
```cpp
unsigned long XY2_100::buildMsg(uint16_t data) {
  unsigned long msg = 0;
  msg = msg | 0;  msg = msg << 1; msg = msg | 0;
  msg = msg << 1; msg = msg | 1;                        // 头部 001
  msg = msg << 16; msg = msg | data;
  msg = msg << 1; msg = msg | XY2_100::parity(data);    // parity() 只对 16 位数据求 XOR
  return msg;
}
uint8_t XY2_100::parity(uint16_t v) {
  uint8_t t = (uint8_t) v ^ v >> 8; t ^= t >> 4; t ^= t >> 2; t ^= t >> 1;
  return (t & 1);
}
```

**【推导】逐位证明二者不等价**：设数据位中 1 的个数为 k，数据位 XOR = k mod 2。

- 参考实现：`P = XOR(001, data) = (1 + k) mod 2` → 全帧 20 bit 中 1 的总数 = 1 + k + ((1+k) mod 2) = **偶数** ✅
- georgemihaila / OPAL：`P = k mod 2` → 全帧 1 的总数 = 1 + k + (k mod 2)。对 k = 0,1,2,3,4 分别得 **1, 3, 3, 5, 5 —— 恒为奇数**，即事实上是**奇校验**。

**【C｜存疑】** 这两个实现"能工作"的可能原因：(a) 目标振镜不检查奇偶位；(b) 只对数据域校验；(c) 使用的振镜恰好接受。**本报告未能找到任何厂商文档说明振镜是否/如何校验 P，也未找到这两个项目对该差异的讨论。**
> **建议**：自行实现时采用 `P = XOR(全部 19 位)`，这是唯一被多个独立解码器交叉验证过的定义。

### 1.4 18 bit 增强模式、XY2-100E / XY2-200，以及一个协议缺陷

**【A｜一手】** 增强模式帧格式（RAYLASE / HALaser 一致）：

```
 19    18    17   16    15 ... 2     1     0
  1            D17..D0 position data          Po
```
> "In enhanced XY2-100E 18 bit operating mode first bit is set to 1, then 18 bit position data followed by a parity bit (**odd** parity) are transmitted."

**【A｜一手】模式一览**（HALaser E1803D Appendix B 原文）：

| 模式 | 帧长 | 帧率 | 分辨率 | 校验 |
|---|---|---|---|---|
| XY2-100 | 20 bit / 10 µs | 100 kHz | 16 bit | 偶 Pe |
| XY2-200 | 20 bit / 5 µs | 200 kHz | 16 bit | — |
| XY2-100E | 20 bit / 10 µs | 100 kHz | **18 bit** | 奇 Po |
| XY2-200E | 20 bit / 5 µs | 200 kHz | **18 bit** | 奇 Po |

> "For the XY2-200 and XY2-200E modes a frame with 20 bits has a length of **5 usec** which is similar to **200 kHz** output frequency."

**【C｜存疑】时钟上限的来源冲突（两个值都列出）**：

| 来源 | 说法 |
|---|---|
| SIGROK 官方解码器 <https://sigrok.org/wiki/Protocol_decoder:Xy2-100> | "XY2-100 is the base variant with a clock frequency of **up to 2 MHz**；XY2-200 is XY2-100 with a clock frequency of **up to 4 MHz**" |
| **RAYLASE SS-III §2.2（一手）** | "**The maximum frequency of the clock is 10 MHz. 4 MHz are recommended.**" |

**【推导】** 推测 SS-III 的 DSP 对帧率不敏感（靠 SYNC 分帧），10 MHz 是接口器件的电气上限而非协议上限；RAYLASE 自家控制卡仍以 2 MHz 输出。**未能找到任何来源说明"10 MHz 时钟下帧内时序/校验如何定义"。**

**【A｜一手】18 bit 与命令帧不可区分 —— 双方官方都承认的协议缺陷**：

> "The reason is that the 18-bit mode is in part indicated by an inverted parity bit (odd parity) while the command mode available in the -E variants uses the default even parity. This means that **it's impossible to determine when a command mode transmission was corrupted as it'll just look like an 18-bit position transmission and vice versa.** The PD emits a warning for this reason, just to make users aware." — SIGROK

> "The distinction between 18Bit target position frame and command frame occur by the different parity. **This can cause that the deflection unit possibly cannot identify parity error any longer.**" — RAYLASE SS-III §3.3.1

**【A｜一手】位置数据被解释为无符号数**：
> "The target position (D15 - D0 or D17 - D0) is interpreted as **unsigned integer** in which D0 is the last significant bit and D15 or D17 the most significant bit."（RAYLASE SS-III §3.3.1）

**【推导】缓解措施（本报告建议，非来源原文）**：命令帧前后插入冗余帧；用回读通道确认命令已生效；关键命令重复发送并核对回读值。

### 1.5 回读（STATUS）通道

**【A｜一手】RAYLASE SS-III §3.3.2：回读通道有 3 种帧型，结构上不可区分**，须由控制卡通过命令帧预先约定：

| 帧型 | 帧头 | 数据 | 校验 |
|---|---|---|---|
| 16Bit Downward Compatible（兼容 SS-II 模拟头） | `0 0 1 1`（4 bit） | D15…D0 | **无** |
| 16Bit 标准 | `0 0 0 1`（4 bit） | D15…D0 | **无** |
| 18Bit | `0 1`（2 bit） | D17…D0 | **无** |

> "Because of the downward compatibility there are three different frame types which are **not distinguishable from each other because of their structure**."

**【A｜一手】标准 XY2-100 STATUS 字位定义**（RAYLASE SS-III SetMode 参数 `0x00`，8 bit 在上/下字节重复）：

| 位（高/低字节） | 含义（1 = 正常） |
|---|---|
| Bit 15 / Bit 7 | =1 轴在工作；=0 故障 |
| Bit 14 / Bit 6 | =1 振镜温度正常（SS-III 恒 OK，未测温） |
| Bit 13 / Bit 5 | =1 Z 轴在跟踪窗口内（SS-III 未实现，恒 1） |
| Bit 12 / Bit 4 | =1 X 轴（小镜）在跟踪误差窗口内 |
| Bit 11 / Bit 3 | =1 Y 轴（大镜）在跟踪误差窗口内 |
| Bit 10 / Bit 2 | =1 自动校准传感器未激活 |
| Bit 9 / Bit 1 | 恒为 0 |
| Bit 8 / Bit 0 | 恒为 1 |

> "Corresponds to the status word of the standard XY2-100 (without -E). The status word consists of 8 Bit which are repeated in upper and lower Byte."

**【A｜一手】跟踪误差窗口可配**（命令 `SetPosAcknowledgeLevel (0x15)`）：
> "The default value is **183** (this equates **0.28% of the service field**). If the position error is greater than tracking error window, PosAck bits are reset to 0..."

**【B｜二手】中文博客给出的是另一套 STATUS 位定义**（博客园 XYMOTION）：
> BACK（STATUS）: BIT19=0, BIT18=0, BIT17=1, BIT16=PSO, BIT15=Pulse, BIT14=X ready, BIT13=Y ready, BIT12=Z ready；BIT9=X error, BIT8=Y error, BIT7=Z error, BIT0=Pe
> 来源：<https://www.cnblogs.com/xymotion/p/12987507.html>

**【C｜存疑】两套定义不一致**，且 SIGROK 也承认至少 3 种变体：
> "The status or feedback signal is unfortunately not straightforward to decode... there are at least **3 different variants**: backwards-compatible 16 bit, standard 16 bit and 18 bit. They can't be distinguished from another and the user would have to specify which to expect."

> **结论：STATUS 通道不是可移植的互操作接口，必须按具体振镜型号的手册实现。**

**【A｜一手】Newson rhothor X7 用单根 STATUS 线（非 20 bit 帧），且语义相反**：
> "The status bit is sent by the deflection system, it is not synchronised with the SENDCK input.
> The STATUS bit is **'0'** when: X 轴位置 < 最大位置误差 且 Y 轴位置 < 最大位置误差 且 X 有效转子电流 < 警告阈值 且 Y 有效转子电流 < 警告阈值 且 数字调节器运行中。
> The STATUS bit is **'1'** when at least one of these conditions is false."

### 2.1 `412910609/galvoMC`（Verilog ★29）—— **唯一可核实的开源 Verilog 实现，且是接收侧**

- 仓库：<https://github.com/412910609/galvoMC>

- README 原文：`1、XY2-100协议的解析；2、振镜X、Y电机脉冲的生成；3、编码器数据采集。`

**要点 / 可借鉴处：**
1. **采样边沿正确**：严格在 `xy_clk` 下降沿移位 → 与数据手册 "when it goes low, the data bit is sampled" 一致。【A】
2. **复位默认值 `16'h8000`（中点）**，不是 0 → offset binary 的正确默认，上电时振镜指向视场中心。【A】
3. **位序验证**：20 bit 移位结果取 `[16:1]` = 去掉最高 3 位（C2C1C0）和最低 1 位（P）。**独立验证了 §1.1 的帧结构。**【推导自源码】
4. **完全没有校验奇偶位** → 该实现不检测传输错误。【推导自源码】
5. **`bit_cnt == 5'd20` 与 `bit_cnt >= 5'd20` 的复位条件交错**，且 END 态依赖由组合逻辑产生的 `finish_flag`（`finish_flag_n` 在 `bit_cnt==20` 时恒为 1），可能与 `bit_cnt_n` 的清零存在同周期竞争。**属可改进点而非确认的 bug**（未做仿真验证）。【C】

构帧、校验与查表（原文）：

```cpp
  uint32_t Ch1 = (((uint32_t)X << 1) | 0x20000ul) & 0x3fffeul;
  uint32_t Ch2 = (((uint32_t)Y << 1) | 0x20000ul) & 0x3fffeul;
  uint8_t parity1 = 0, parity2 = 0;

  // 0123456789abcdef
  // fedcba9876543210
  // every 16-bit word generates a clock pulse also
  const uint16_t Sync1[4] = { 0xd2c3, 0x9687, 0x5a4b, 0x1e0f  };
  const uint16_t Sync0[4] = { 0xf0e1, 0xb4a5, 0x7869, 0x3c2d  };

  for(int i=0; i<20; i++) {
    if(Ch1 & (1 << i)) parity1++;
    if(Ch2 & (1 << i)) parity2++;
  }
  if(parity1 & 1) Ch1 |= 1;      // 偶校验：统计范围 = bit0..bit19（含 C0=bit17）
  if(parity2 & 1) Ch2 |= 1;

  // Clock cycle: 1-0, Sync 111...0
  for(int i=19; i>=0; i--) {
    int j = 0; uint32_t d;
    if(Ch1 & (1 << i)) j = 1;
    if(Ch2 & (1 << i)) j |= 2;
    d = Sync1[j];
    i--;
    j = 0;
    if(Ch1 & (1 << i)) j = 1;
    if(Ch2 & (1 << i)) j |= 2;
    if(i != 0) d |= (uint32_t)Sync1[j] << 16; else d |= (uint32_t)Sync0[j] << 16;
    *p++ = d;
  }
```

有符号坐标映射（原文）：

**【推导自源码】要点：**
- `(X << 1) | 0x20000` 且掩码 `0x3fffe` → bit17 = 1（C0）、bit16..bit1 = D15..D0。发送循环从 i=19 递减到 0，故实际发送 bit19,18,17 = **0,0,1 → 帧头 001 正确**。
- `Sync1`/`Sync0` 两张表承载"时钟脉冲 + SYNC 电平 + 2 位数据"，`Sync0` 与 `Sync1` 的差异即 **SYNC 拉低 + 校验位取值**。
- **10 µs/帧的验证**：40 次 DMA 写 @ 4 MHz = 10 µs ✅ 与 100 kframes/s 完全吻合。
- **`setSignedXY()` 做 offset binary 转换：-32768…32767 → 0…65535，中点 0x8000。**【A】

ISR（原文）：
```cpp
void XY2_100::QT1_isr() {
  TMR1_CSCTRL1 &= ~(TMR_CSCTRL_TCF1);
  asm volatile ("dsb");                   // wait for clear memory barrier
  GPIO6_DR = ( GPIO6_DR & ~(GPIO6_DR) ) | (d);
  if(ClkHiLo) {
    d = 0UL;
    cbitx = activePacketX[bitCount];
    cbity = activePacketY[bitCount];
    d = (d & ~(1UL << 18)) | (cbity << 18);
    d = (d & ~(1UL << 16)) | (cbitx << 16);
    //WRITE SYNC
    if(bitCount >= 19) {
      bitCount = -1;
      d = (d & ~(1UL << 22)) | (0 << 22);   // SYNC 拉低（第 20 位 = 校验位）
      if(hasData == 1) { /* 切换双缓冲包指针 selector */ }
      hasData = 0;
    } else {
      d = (d & ~(1UL << 22)) | (1 << 22);   // SYNC 保持高
    }
    d = (d & ~(1UL << 24)) | (1 << 24);     // 时钟拉高
    bitCount++;
  } else {
    d = (d & ~(1UL << 24)) | (0 << 24);     // 时钟拉低
  }
  ClkHiLo = !ClkHiLo;
}
```

**【推导自源码】要点：**
- `bitCount` 0…19；`bitCount >= 19`（第 20 位）时 SYNC 拉低 → **SYNC 高 19 位、第 20 位（校验位）低**，与数据手册一致 ✅
- **ISR 内整字写 GPIO**（`GPIO6_DR` 一次写 X/Y/SYNC/CLK 四根线），避免逐位 `digitalWrite` 的分裂。这是 MCU 位操作方案的关键优化。
- 用 `asm volatile ("dsb")` 做内存屏障。
- **包缓存双缓冲 + `hasData`/`selector`**：新数据未就绪时自动重发上一帧 → **避免 FIFO 断流导致振镜失步**（重要健壮性设计，见 §4.6）。
- **注意：`parity()` 只对 16 位数据求 XOR**（见 §1.3），与参考实现不一致。

### 3.4 ESP32：纯软件 GPIO 位翻转（`txpzyr/xy2_100`）

来源（原文件为 GBK 编码）：<https://raw.githubusercontent.com/txpzyr/xy2_100/master/xy2_100.ino>

```cpp
#define  CLK 2
#define  SYNC 4
#define  DATA_X 16
#define  DATA_Y 17

#define T_UP 15
#define T_DOWN 7

//pin1-4 需要相对GND有1.2v      <- 硬件注释（见 §5.2）

#define PinH(pin) GPIO.out_w1ts = ((uint32_t)1 << pin)
#define PinL(pin) GPIO.out_w1tc = ((uint32_t)1 << pin)
#define PinV(pin, value) value==0?PinL(pin):PinH(pin)
#define CLKH PinH(CLK)
#define CLKL PinL(CLK)
#define SYNCH PinH(SYNC)
#define SYNCL PinL(SYNC)

void XY2_Send_First_Bit(bool x) {
	PinV(DATA_X, x); PinV(DATA_Y, x);
	SYNCH;                       //同步拉高
	CLKH;                        //clock拉高
	for (int i = 0; i < T_UP; ++i) NOP();
	CLKL;
	for (int i = 0; i < T_DOWN; ++i)	NOP();
}

void XY2_Send_byte(uint16_t tx, uint16_t ty) {
	SYNCH;
	for (t = 0; t < 16; t++) {
		uint16_t x = (tx & 0x8000) >> 7;
		uint16_t y = (ty & 0x8000) >> 7;
		PinV(DATA_X, x); PinV(DATA_Y, y);
		tx <<= 1; ty <<= 1;
		CLKH; for (...) NOP(); CLKL; for (...) NOP();
	}
}

void XY2_Send_Last_Bit(bool px, bool py) {
	PinV(DATA_X, px); PinV(DATA_Y, py);
	SYNCL;                       //同步拉低
	CLKH; ... CLKL; ...
	SYNCH;
}
```

**【推导自源码】要点：**
- 用 ESP32 的 `GPIO.out_w1ts / out_w1tc` 寄存器**一次性置位/清零**，比 `digitalWrite` 快得多——ESP32 位操作方案的正确做法。
- 运行在**独立 FreeRTOS 任务（pinned to core 0）**，并 `disableCore0WDT()` 关闭看门狗（任务是死循环）。
- **未使用 ESP32 的 RMT / I2S / LEDC 外设**（见 §3.1 的"未找到公开数据"）。
- 校验 `px = !parityCheck(cx)`，`parityCheck` 是 16 位 popcount 奇偶 → 又是指对数据位的校验（§1.3 第二类）。
- 坐标中心取 32000（示例代码的近似，非 32768）。
- **`T_UP=15 / T_DOWN=7` 表明占空比被刻意做成不对称**（高电平约为低电平 2 倍）。**作者没有留下任何注释解释这个不对称**，故只能标记为观察到的现象。见 §4.7。

### 3.5 STM32H743：SPI `DSIZE=20` + DMA 双缓冲，无需 FPGA（`belikoff16/XY2-100-`）

来源：<https://raw.githubusercontent.com/belikoff16/XY2-100-/main/Core/Src/SPI_DMA_Double_buffer.c>
仓库描述：*"The xy2-100 Laser Galvo protocol on the stm32h743 microcontroller **without using FPGA**"*

**本报告认为这是最优雅的 MCU 方案：把"一帧 = 一次 SPI 传输"直接映射到硬件。** 关键配置（原文注释保留）：

```c
	SPI1->CFG1 = SPI_CFG1_TXDMAEN          // 允许 DMA
			| (20 - 1)                     // Bits 4:0 DSIZE[4:0]: number of bits in a single SPI data frame => 20 bit!
			;
	// Bit 24 CPHA: clock phase - 0: the first clock transition is the first data capture edge
	SPI1->CFG2 |= SPI_CFG2_SSM             // 软件 SS
			| SPI_CFG2_CPOL                // 1: SCK signal is at 1 when idle   <<<< 关键：CPOL = 1
			| SPI_CFG2_COMM_0              // 01: simplex transmitter
	;
```

**【推导自源码】为什么这是正确的：**
- SPI `CPOL=1, CPHA=0` 意味着：SCK 空闲为高，**第一个跳变沿（下降沿）= 采样沿**，即主机在**下降沿采样 MISO**、在**上升沿更新 MOSI**。
  → 对应 XY2-100：**数据在 CLK 上升沿变化、在下降沿被振镜采样** ✅ 与数据手册完全一致。（对比：常见误区是选 CPOL=0/CPHA=0，那样数据在下降沿变化、上升沿采样，**正好相反**，见 §4.1。）
- `DSIZE = 20` 让一次 SPI 帧正好等于一个 XY2-100 帧（20 bit），无需软件拼帧。这是 STM32H7 SPI 支持 4–32 bit 数据帧带来的便利。
- **SPI1 / SPI2 配置为从机、SPI3 配置为主机**：`SPI3->CFG2 |= SPI_CFG2_MASTER;`，SPI3_CLK 在 `PC10`，SPI1_SCK 在 `PA5`，SPI2_SCK 在 `PB10`。**【推导，源码未写注释说明】** 推测：用 SPI3 产生一路共享的 2 MHz 时钟，物理上同时送入 SPI1/SPI2 的 SCK 引脚，使多个 20 bit 流严格同相，X/Y（+Z）天然同步，无需软件对齐。
- DMA 使用**双缓冲模式（DBM）+ 循环**：
  ```c
  DMA1_Stream0->CR |= DMA_SxCR_DBM           // double-buffer mode
                    | DMA_SxCR_MSIZE_1 | DMA_SxCR_PSIZE_1   // 32-bit
                    | DMA_SxCR_MINC
                    | DMA_SxCR_DIR_0;        // memory-to-peripheral
  DMA1_Stream0->NDTR = data_buf_size/2;
  DMA1_Stream0->M0AR = (uint32_t)data_buf1;
  DMA1_Stream0->M1AR = (uint32_t)data_buf2;
  DMAMUX1_Channel0->CCR |= 38;               // 38 spi1_tx_dma
  ```
  → **DMA 永不停歇地循环发送，天然满足"连续自由运行"要求**（§4.5）。
- 空闲填充值：`bTxBuffer[i] = 0xFFFFE;` = 20 bit 的 `1111_1111_1111_1111_1110`。**【推导】** 控制字 111 是命令帧/非法帧，多数振镜会忽略，可作为"无操作"填充。

**【C｜存疑】** 该工程未写 README，作者未说明实测结果；上述 SPI 主从共享时钟的推断来自寄存器配置，**未经作者确认**。仓库包含大量 CubeIDE 生成文件与 `.o`/`.elf` 构建产物。

### 3.6 STM32 QSPI：把 4 线 QSPI 当作 4 bit 并行移位器（`hyperchao0/qspi4xy2-100`）

来源：<https://github.com/hyperchao0/qspi4xy2-100>、<https://raw.githubusercontent.com/hyperchao0/qspi4xy2-100/main/qspi4xy2-100.h>

**最巧妙的技巧：用 QSPI 的 IO0~IO3 四根数据线同时承载 SYNC / X / Y / Z，每个字节 = 2 个时钟。**

引脚映射（README 原文表格）：

| Quad SPI 引脚 | XY2-100 功能 | 极性 |
|---|---|---|
| CLK | CLK | — |
| NCS | 未使用（可用作 busy 信号或差分驱动器片选） | — |
| IO0 | SYNC | + |
| IO1 | Channel X | + |
| IO2 | Channel Y | + |
| IO3 | Channel Z | + |

构帧代码（**完整原文**，<https://raw.githubusercontent.com/hyperchao0/qspi4xy2-100/main/qspi4xy2-100.h>）：

```c
static inline void q4x_make_buffer(uint8_t *buf, uint16_t x, uint16_t y, uint16_t z) {
    // Initialize buffer
    buf[0] = 0x88;
    buf[1] = 0xF8;
    for (int i = 2; i < 9; i++) buf[i] = 0x88;
    buf[9] = 0x80;
    // Initialize parity
    bool xp = 1, yp = 1, zp = 1;
    // Fill buffer
    for (uint8_t i = 0; i < 16; i++) {
        uint8_t j = i / 2;
        if (i % 2 == 0) {
            if (x & (0x8000 >> i)) { buf[1 + j] |= 0x04; xp = !xp;}
            if (y & (0x8000 >> i)) { buf[1 + j] |= 0x02; yp = !yp;}
            if (z & (0x8000 >> i)) { buf[1 + j] |= 0x01; zp = !zp;}
        } else {
            if (x & (0x8000 >> i)) { buf[2 + j] |= 0x40; xp = !xp;}
            if (y & (0x8000 >> i)) { buf[2 + j] |= 0x20; yp = !yp;}
            if (z & (0x8000 >> i)) { buf[2 + j] |= 0x10; zp = !zp;}
        }
    }
    // Set parity
    if (xp) buf[9] |= 0x04;
    if (yp) buf[9] |= 0x02;
    if (zp) buf[9] |= 0x01;
    // Invert buffer
    // for (int i = 0; i < 10; i++) buf[i] = ~buf[i];
}
```

**【推导自源码】逐位解码，完全验证 §1.1 的帧结构：**
- 每字节 = 2 个 QSPI 时钟，高半字节先发。bit7/bit3 = SYNC，bit6/bit2 = X，bit5/bit1 = Y，bit4/bit0 = Z。
- `buf[0] = 0x88` = 两个半字节都是 `1000` → SYNC 高、XYZ 全 0 → 帧头前 2 位 `0 0`。
- `buf[1] = 0xF8`：第一时钟 SYNC=1 且 XYZ=1 → 帧头第 3 位 `1`；第二时钟 = D15。
- `buf[1..8]` 的 bit7=1、bit3=1 → **SYNC 在时钟 1–18 保持高**；`buf[9] = 0x80` → 第一时钟（第 19 位 = D0）SYNC 仍高，第二时钟（第 20 位 = 校验位）SYNC = 0 ✅
- 校验初值 `xp = 1`（因为帧头 `001` 里有一个 1），每遇到数据位 1 就翻转 → `P = XOR(C2,C1,C0,D15..D0)` ✅ **属 §1.3 的第一类（正确）定义。**
- 被注释掉的 `// Invert buffer` 值得注意：**若取消注释，所有信号（含 SYNC）整体反相**——通常是调试时钟极性时留下的临时改动。

README 中的配置与硬件建议（原文）：
> - Clock prescaler. The clock frequency should set to 2MHz. That means the prescaler value should the (Freq_QSPI / 2MHz) - 1.
> - FIFO threshold. The FIFO threshold should be set to 1.
> - **No sample shift. The data should be sampled on the rising edge of the clock signal.**
> - Chip select high time. The chip select high time should be set to 1 cycle.
> - **Clock mode. The clock mode should be set to Low.**

> The XY2-100 protocol uses a default high polarity for the clock signal and a default low polarity for the synchronization signal. The data signals are sampled on the falling edge of the clock signal. **We can change the polarity of the clock signal by swapping the clock output pins of the differential line driver.**
> **Note:** To avoid the high impedance state of the differential line driver, the output of the line driver should be connected pull-up or pull-down resistors.

> The XY2-100 protocol is a differential protocol. Therefore, the QSPI pins must be connected to a differential line driver. **A AM26LS31 is a good choice for this purpose, it works with 5V power supply and accepts 3.3V TTL input signals. The output of the AM26LS31 is TIA/EIA-422 compatible**, so it can be connected to most XY2-100 devices directly.

**【C｜存疑｜重要】** STM32 QSPI 的 `ClockMode` 只有 `QSPI_CLOCK_MODE_0`（CPOL=0/CPHA=0）与 `QSPI_CLOCK_MODE_3`（CPOL=1/CPHA=1）两种。CPOL=0/CPHA=0 时 QSPI **在 CLK 下降沿更新数据、在上升沿采样**，因此 SCK 送给振镜后，振镜在**下降沿**采样的正是数据**正在变化**的时刻——理论上处于亚稳态窗口。
作者给出的补救办法是**交换差分驱动器的 CLK+/CLK− 输出引脚（即反相时钟）**，这样振镜的"下降沿"就对应 QSPI 的"上升沿"，数据已稳定。**本报告认为这是该方案能工作的真正原因**，但作者未展开论证，README 中"Clock mode should be set to Low"与"swap clock output pins"两句在表述上互相牵扯，**故列为存疑，建议自行用示波器确认采样点。**

### 3.7 RP2040 PIO：3 个状态机 + 硬件集成（`earlynerd/XY2Galvo`，基于 `Megatokio/Laseroids`）

来源：<https://github.com/earlynerd/XY2Galvo>、<https://raw.githubusercontent.com/earlynerd/XY2Galvo/main/src/XY2-100.pio>

**本次调研中找到的、注释最详尽、对陷阱说明最清楚的发送侧实现。** PIO 汇编原文：

```pio
; -----------------------------------------------------------------------
; XY2-100 Interface
; clock for all state machines must be 8 MHz
; cpu must write channel x and y data before laser ON/OFF control data
; data should be pushed by software (not dma) for easier stalling on full TX fifo
; -----------------------------------------------------------------------
.define public XY2_SM_CLOCK 8000000	; all SMs of the XY2 IF use the same clock
.define HIGH 0b01       ; pin N = 1,  pin N+1 = !1
.define LOW  0b10       ; pin N = 0,  Pin N+1 = !0

; -----------------------------------------------------------------------
; generate 2MHz clock and sync pulse on Parity bit
; SIDESET:	clock+ and clock- pins are SIDESET PINS 0, 1
; 			sync+  and sync-  pins are SIDESET PINS 2, 3
; Synchronization: The startup delay is 4cc (during which a 'parity bit' cycle is emitted)
.program xy2_clock
.side_set 4
.define SYNC_HIGH  HIGH*4
.define SYNC_LOW   LOW*4
.define CLOCK_HIGH HIGH
.define CLOCK_LOW  LOW

.wrap_target
public start:
    nop			side (SYNC_LOW + CLOCK_HIGH) 	[1]	; bit 20: parity
    set x, 18	side (SYNC_LOW + CLOCK_LOW)		[1]	; => 19 loops
a:	nop			side (SYNC_HIGH + CLOCK_HIGH) 	[1]	; bits 1..19
    jmp x-- a	side (SYNC_HIGH + CLOCK_LOW)	[1]
.wrap
```

数据状态机（**奇偶校验用"程序流"实现，而非软件预计算**）：

```pio
.program xy2_data
.side_set 2 opt         ; the data+ and data- pins
; shift must be configured to pull_threshold=32 because we shift out msb first
;   and the SM throws away the upper 16 bits
next_word:
	jmp pin, tx_empty	side DATA_LOW	[3]
tx_not_empty:
    pull block  						; load OSR from TX fifo	((should also work with BLOCK))
    mov x, osr                      	; store value for possible repeat.
	jmp tx			[1]					; note: does not 'empty' the OSR
tx_empty:
    mov osr,x		[3]					; reload OSR from old value
tx: out null,16  side DATA_HIGH [1]		; skip upper bits;  side-set: last bit of '001' header

; parity is currently 'even':
loop_even:
    out y, 1            	            ; get next data bit
    jmp !y, send_0_even
send_1_even:
    jmp loop_end_odd  side DATA_HIGH    ; bit '1'  and toggle to parity odd
send_0_even:
    jmp loop_end_even side DATA_LOW     ; bit '0'  and keep parity even
; parity is currently 'odd':
loop_odd:
    out y, 1                	        ; get next data bit
    jmp !y, send_0_odd
send_1_odd:
    jmp loop_end_even  side DATA_HIGH   ; bit '1'  and toggle to parity even
send_0_odd:
    jmp loop_end_odd  side DATA_LOW     ; bit '0'  and keep parity odd
loop_end_even:
    jmp !osre, loop_even
    nop [1]
    jmp next_word  side DATA_HIGH [3]   ; send PE = '1'
loop_end_odd:
    jmp !osre, loop_odd
    nop [1]
public start:
    jmp next_word  side DATA_LOW [3]    ; send PE = '0'
```

**激光控制状态机及其关键警告（原文注释，本报告认为这是最重要的工程提示之一）：**

```pio
; The SM expects 10 bit of data controlling the laser during one XY2 frame.
; The bits is shifted out LSB first with 1 MHz.
; The laser data immediately controls the laser while the X/Y data is transmitted.
; => the laser control signal takes effect more than 1 frame before the scanner moves
; 	 and must be delayed accordingly by the application.
;	 The scanner will probably add some more delay on it's own.
```

**【推导自源码】要点：**
- **奇偶校验用"当前奇偶状态"两个循环（`loop_even` / `loop_odd`）+ 状态转移实现**，完全在 PIO 内完成，零 CPU 开销。**属 §1.3 的第一类（对整个 19 位做偶校验）。**
- **`tx_empty` 分支 = FIFO 断流时重发上一帧**：`mov osr, x`（x 里存着上一帧的值）。注释写明 *"if fifo runs dry then data must be repeated / we can't simply pull non-blocking, because fifos are not written at the same time"*。**这是"FIFO 断流"陷阱的正面解法。**
- **差分信号用 `side_set` 一次设置一对引脚**（`HIGH = 0b01` 表示 pin N=1、pin N+1=0），是**互补推挽式"伪差分"**，而非真正的 RS-422 驱动器。
- 时钟状态机注释里的 **"startup delay is 4cc" / "startup delay is 5cc"** 说明作者花很大力气对齐 4 个状态机的相位。
- 状态机时钟 8 MHz，`[1]` 延时 = 1 个 SM 周期 = 125 ns，一个时钟周期 = 2 指令 ×(1+1) 周期 = 4 SM 周期 = 500 ns → 2 MHz ✅
- 该库实现了**激光延时补偿**：`static uint laser_delay_size = 14; // From LASER_QUEUE_DELAY`，用长度 14 帧的环形队列延迟激光信号 → **14 × 10 µs = 140 µs**。见 §6.5。

`XY2Galvo.h` 中的延时/速度模型（原文）：
```cpp

constexpr float SCANNER_WIDTH = 0x10000;

struct LaserSet {
	float speed;

```

## 4. 具体工程陷阱

### 4.1 陷阱一：SPI 时钟相位/极性选错（最高频错误）

**规范要求**【A｜一手】：*"When it goes high, the data bit changes. When it goes low, the data bit is sampled by the deflection system."*
即：**数据在上升沿变化 → 稳定 → 下降沿被采样**。

映射到 SPI 模式（Mode = CPOL/CPHA）：

| SPI 模式 | CPOL | CPHA | 数据变化沿 | 采样沿 | 是否符合 XY2-100 |
|---|---|---|---|---|---|
| Mode 0 | 0 | 0 | 下降沿 | 上升沿 | ❌ **正好相反** |
| **Mode 1** | **0** | **1** | **上升沿** | **下降沿** | ✅ **正确** |
| Mode 2 | 1 | 0 | 上升沿 | 下降沿 | ✅ 正确（STM32 记法：CPOL=1, CPHA=0） |
| Mode 3 | 1 | 1 | 下降沿 | 上升沿 | ❌ 相反 |

> **⚠️ 命名坑**：STM32 的 SPI 只有 `CPOL` 与 `CPHA` 两个独立位，**没有"Mode 1"这个枚举**。`belikoff16` 的实现就是 `CPOL=1 + CPHA=0`（等价上表 Mode 2），它才是正确答案。
> STM32 **QSPI** 外设更受限，只有 `QSPI_CLOCK_MODE_0`（CPOL=0/CPHA=0）与 `QSPI_CLOCK_MODE_3`（CPOL=1/CPHA=1）——**两个都不是 XY2-100 需要的相位**。`hyperchao0` 的解决办法是**在差分驱动器上交换 CLK+/CLK−**（把时钟整体反相）。【C｜存疑，见 §3.6】

**验证过的正确配置**【A｜一手】（`belikoff16/XY2-100-`，STM32H743）：
```c
SPI1->CFG2 |= SPI_CFG2_SSM
            | SPI_CFG2_CPOL        // 1: SCK signal is at 1 when idle
            ;                      // CPHA = 0 (默认)：第一个跳变沿 = 采样沿 => 即下降沿采样
SPI1->CFG1 |= (20 - 1);            // DSIZE = 20 bit，一帧 = 一次 SPI 传输
```

**排查手段**：用示波器同时看 CLK 与 DATA，确认**数据跳变发生在时钟上升沿之后、并在整个低电平期间保持稳定**。若数据跳变与下降沿同时发生 → 相位选反。

### 4.2 陷阱二：SYNC 对齐（19 位高 + 第 20 位低）

**【A｜一手】** 规范：*"It remains high for 19 bits and goes low when the parity can be sent."*
**【A｜一手】** RAYLASE SS-III：*"The last bit of a frame is shown by a '0' on the SYNC line pair (The SYNC line pair serves as latch signal)."*

必须做到：
1. **SYNC 与第 1 位（C2）同沿上升**，不能提前也不能滞后。
2. **SYNC 恰好在第 19 位结束后拉低**，即**低电平只覆盖第 20 位（校验位）**。
3. SYNC 高电平期间必须覆盖 C2…D0 共 19 位。

**四种独立实现完全一致**：
- `Tuet/XY2_100`：查表 `Sync0` vs `Sync1`，"Sync 111...0" 注释【A】
- `MiniGalvoControl`：`if(bitCount >= 19) { ... SYNC=0 } else { SYNC=1 }`，bitCount 0…19【推导自源码】
- `hyperchao0/qspi4xy2-100`：`buf[0..8]` 的 SYNC 位均为 1，`buf[9] = 0x80` 使第 20 个时钟 SYNC 为 0【推导自源码】
- `earlynerd/XY2Galvo` PIO：`xy2_clock` 程序显式注释 `; bit 20: parity` 单独一个 `SYNC_LOW` 循环，其余 19 次 `SYNC_HIGH`【A】

**常见错误**：把 SYNC 写成"高 20 位"或"高 18 位"；或在发出校验位后才拉低 SYNC（会被振镜当成帧长 21 位）。`danmcb/Saleae-XY2-100` 解码器专门为此设了 `sync_ok` 标志：只要在**前 19 位期间** SYNC 为低，或在**第 20 位** SYNC 为高，就报 `SYNC_ERROR_FLAG`。【A】
```cpp
// danmcb/Saleae-XY2-100 的判定逻辑
if (mSync->GetBitState() == BIT_LOW) sync_ok = false;   // 前 19 位：SYNC 必须为高
...
// now the last bit (sync/parity)
if (mSync->GetBitState() == BIT_HIGH) {
    // this is a framing error, we try to resync
    sync_ok = false;
    mSync->AdvanceToNextEdge(); // sync is low
    mSync->AdvanceToNextEdge(); // sync is high
}
```

### 4.3 陷阱三：奇偶校验统计范围

**一句话**：`P = XOR(C2,C1,C0,D15…D0)`（5 个独立参考实现一致）。**不要**只对 D15…D0 求 XOR——那会得到事实上的奇校验，是 18 bit 模式的约定。详见 §1.3。

### 4.4 陷阱四：命令帧 / 18 bit 帧不可区分（协议固有缺陷）

见 §1.4。**一句话**：一个位翻转的命令帧会恰好变成合法的 18 bit 位置帧，反之亦然 → **命令帧的传输错误无法被检出**，且振镜可能把损坏的命令当成一个极端位置指令执行。

### 4.5 陷阱五：时钟是否必须连续自由运行？时钟停止会怎样？

**【A｜一手】** 厂商文档把"连续"写死在引脚定义里：
> Pin 1/14 — **CLOCK-/CLOCK+ — CLOCK : Continuously running clock** — Input
> — Ray-motion XY2-100 datasheet；Newson rhothor X7（信号名 `SENDCK`）同样写作 "Continuously running clock"

**【A｜一手】时钟/同步出错时的可观测行为（RAYLASE SS-III 面板 LED 说明，原文）：**
> **PX** — Illuminates red if a parity error occurs on the X-channel of the XY2-100 Interface. **Illuminates permanently if clock or sync signal of the XY2-100 interface has an error.** The illumination period has been extended to make short failures visible too.
> **PY** — （同上，Y 通道）
> **DX** — Illuminates yellow if the data on the X-channel of the XY2-100 interface changes. The illumination period has been extended to make single data changes visible too.
> **EX / EY** — Illuminates red in case of an error on the X-/Y-axis and during the booting of the axis. The booting process lasts a few seconds. **If this LED illuminates the output stage of the X-/Y-axis is deactivated.**
> 来源：<http://www.alaser.com.tw/db/upload/webdata4/5alaser_201412422541519318.pdf> §5 Status-LEDs

**【推导】由此可得可靠结论：**
1. 振镜**能检测** clock/sync 异常，并会**点亮常亮故障指示**——"时钟停止"是一个**被监控的故障条件**。
2. **时钟或同步出错时轴故障 LED 点亮，输出级被关闭（output stage deactivated）**——即振镜**不是**简单地"保持最后位置"，而是**关闭功率输出**（镜片失去保持力矩）。**这点对安全设计很重要。**
3. **"保持最后位置"这一说法：未找到任何厂商文档明确承诺**，标记为**未找到公开数据 / 不推荐依赖**。

**【A｜一手】旁证**：STATUS 字的 Bit 15/7 = "axis at work; = 0 : failure" 提供了软件可读的故障位（§1.5）。

**【推导】反面证据：协议本身对时钟频率不敏感。**
- 帧边界由 SYNC 上升沿界定，与时钟速度无关（§1.1、§1.2）。
- `georgemihaila` 作者自述 Arduino Nano 慢速位操作 "seems to be able to drive a galvo just fine"。
- RAYLASE SS-III 允许 10 MHz 上限、4 MHz 推荐 → 振镜内部对帧率有很宽的容忍范围。
→ **结论：时钟可以慢，但不能停。** 空闲期也必须继续输出时钟与 SYNC 帧（通常是"重复发送当前位置"），这正是 `georgemihaila` 的 `tickingDelay()` 在做的事（§3.8）。

### 4.6 陷阱六：帧率（100 kHz）与振镜带宽不匹配 —— 振镜内部插值

**【A｜一手】RAYLASE SS-III 命令 `SetInterpolation (0x90)`（原文，Table 2）：**
> **Bit 7 downto 1** — Maximum interpolation time in 2 micro seconds ( 0 => 0us, 1 => 2us, … , 127 => 254us)
> In case that the command position is delivered via XY2-100 in smaller intervals than set here, **a linear interpolation between the two neighboring command positions is executed then.**
> But **the movement of the axis is delayed by this adjusted interpolation time then.** E.g. the entire tracking delay time is enlarged about this time. **The main tracking delay of the position control doesn't change (edges of marked objects are not rounded, they are only drawn a short time later. If necessary the laser delay times have to be adjusted).**
> **Default: 120us (60)**
>
> **Bit 0** — If this bit is set to '1', the **once repeated command position is ignored**. This is necessary on the control cards SP-ICE-1 PCI PRO or SP-ICE-2 for the operating of SS-III as **these cards transmit each command position twice consecutively. When both identical command positions are considered in the interpolation, a saw tooth like form of the command position exists after the interpolation.** **Default: '1' (active)**

**【A｜一手】另一条佐证：命令帧会挤掉一次位置更新**
> "Since during the command frame lasting **10µs** no target position can be transmitted the deflection unit **interpolates the missing position information from the nearest two sampling points** sent by the control card."（SS-III §3.4）

**【推导】本报告关于"更新率 vs 带宽"最重要的工程结论：**
1. **100 kHz 的指令流是"过采样 + 内部插值"，不是"振镜真的以 100 kHz 运动"。** 振镜机械响应只有亚 kHz~kHz 量级（§7.5），它把 100 kHz 的点列做线性插值后送给位置环。
2. **默认插值时间 120 µs 意味着：一个点的指令最多要等约 120 µs 才被"走完"。** 这直接决定激光延时参数的量级（§6）。
3. **插值不会让拐角变圆**（原文："edges of marked objects are not rounded, they are only drawn a short time later"）——插值是把整条轨迹**整体延后**，而不是低通滤波。**变圆是位置环跟踪误差导致的，是另一回事。**
4. **发送位置数据的间隔大于插值时间设置时，插值不生效**（变成"直连"），轨迹出现台阶。**因此控制卡必须保证位置帧到达间隔 ≤ 插值时间设置值。**
5. **重复发送同一位置会引入锯齿**（若 Bit 0 = 0）——控制卡的帧率与振镜插值设置必须协同配置。

> **【未找到公开数据】** 其他厂商（SCANLAB、CTI、Sino-Galvo 等）振镜内部是否也有类似插值、默认值多少。请查阅具体型号手册。

### 4.7 陷阱七：时钟抖动与占空比

**【A｜一手】** 规范只给出数据侧的建立/保持时间（tDS ≥ 50 ns，tDH ≥ 100 ns）。**【未找到公开数据】** 规范**未规定时钟占空比、抖动（jitter）、上升/下降时间**。

**【推导】由 tDS/tDH 反推电气余量**：
- 周期 T = 500 ns（2 MHz）。满足 tDS ≥ 50 ns + tDH ≥ 100 ns 共需 150 ns 稳定窗口。
- 若占空比 = 50%（高 250 ns / 低 250 ns），且数据在上升沿后 tD 秒稳定，则下降沿前后各有约 (250 − tD) ns 余量。**250 ns 对 50/100 ns 的要求是 2.5~5 倍裕量**，说明规范对占空比并不苛刻，但**严重抖动（例如软件位操作被中断打断）会直接吃掉这个裕量**。
- `txpzyr` 的 ESP32 实现刻意用了 `T_UP=15, T_DOWN=7`（高电平约为低电平 2 倍）。**【推导】** 可能是为了在软件延时抖动下让数据位有更长稳定时间，但**作者没有留下任何注释解释**，故只能标记为观察到的现象。

**【推导】实测建议**：用示波器同时观察 CLK 与 DATA，检查
1. 每个数据位的稳定窗口是否 ≥ 150 ns；
2. 帧周期是否稳定在 ~10 µs（若抖动 > 数百 ns，说明软件路径被抢占）；
3. 是否存在时钟毛刺（软件位操作或 DMA 冲突时常见）。

### 4.8 陷阱八：地噪声 / 屏蔽 / 差分 / 走线

## 5. 电平标准与差分接口

> 📎 本节的完整版（含 26 份器件数据手册核算、逐条 URL 清单）见同目录 **《调研笔记-电气与规格》**。以下为结论与关键证据。

### 5.1 差分标准：**RS-422，不是 LVDS**

**【A｜一手】RAYLASE 官方推荐器件（SS-III XY2-100-E 文档 §2.2 原文全句）**：
> **The maximum frequency of the clock is 10 MHz. 4 MHz are recommended.**
> **As line driver UA9638CD is recommended. As line receiver MAX3096 or UA9637 are recommended. Alternativly AM26LV32 can also be used.**

| 器件 | 类型 | 标准 | 在生态中的角色 |
|---|---|---|---|
| **AM26LS31CD** | 四路差分线驱动器 | 5 V，ANSI TIA/EIA-422B + ITU V.11 | ★ **`hyperchao0/qspi4xy2-100` 实测在用（全板唯一 IC）** |
| **SN75174N** | 四路差分线驱动器（带三态与使能） | 5 V，EIA/TIA-422-B + RS-485 + V.11 | ★ **`leswright1977/OPAL_PCB` 实测在用** |
| **CD74HC4050E** | 六路缓冲/电平转换 | 3.3 V → 5 V | OPAL_PCB：抬升 SSR/PWM 逻辑电平（不驱动差分对） |
| **UA9638CD** | 双路差分线驱动器 | 5 V，ANSI EIA/TIA-422-B | **RAYLASE 官方推荐驱动器** |
| **UA9637** | 双路差分线接收器 | 5 V RS-422 | **RAYLASE 官方推荐接收器** |
| **MAX3096** | 四路 RS-422/485 接收器 | ±15 kV ESD，VTH ±200 mV，共模 −7…12 V，RIN ≥48 kΩ | **RAYLASE 官方首选接收器** |
| **AM26LV32** | 四路差分线接收器 | 3.3 V，±200 mV 灵敏度，共模 −0.3…5.5 V | **RAYLASE 官方备选接收器** |

> **【A｜一手】结论：XY2-100 的物理层 = 5 V / 3.3 V 供电的 RS-422（TIA/EIA-422）差分。**
> 【未找到公开数据】任务清单中点名的 `AM26C31`、`SN75175`、`SN65LVDS047`/`DS90LV047A`/`DS90LV048A`、`MAX490`/`MAX491`、`74LVX`/`74LVC`、`IL712`/`IL715`、`ADN4651`、`Si8642` —— **均未找到任何真实振镜设计使用它们的证据**（只找到器件数据手册，没有设计实例）。**不建议在无实测的前提下用 LVDS 器件替代 RS-422 器件**：差分摆幅（LVDS ≈ 350 mV vs RS-422 ≈ 2 V）与共模范围都不同。

**【A｜一手】LinuxCNC 论坛实践旁证**（间接印证"26LS31 一颗芯片就够"）：
> "XY2-100 needs at minimum 3 differential outputs (X data, Y data and clock) so you would likely need some kind of daughter-card like a Mesa ENC422 that converts single ended TTL level signals to differential signals. … (**The converter is really just one chip (26LS31 equivalent on a small PCB)**)"
> 来源：<https://forum.linuxcnc.org/additive-manufacturing/58213-galvo-head-protocol-xy2-100>【B】

### 5.2 单端 TTL 能否直连？

**【A｜一手｜明确肯定】`Tuet/XY2_100` README 原文**：
> "As the Teensy outputs **3.3V signals in a differential fashion**, for **short cables it can be directly connected to the galvanometer**. For reliable purpose the usage of RS485 drivers with galvanic isolation is strongly recommended."

引脚接法（原文）：
```
  Required Connections
  --------------------
    pin  2: CLOCK+        pin  6: CLOCK-
    pin 14: SYNC+         pin 20: SYNC-
    pin  7: CHAN1+        pin 21: CHAN1-
    pin  8: CHAN2+        pin  5: CHAN2-
```
> ⚠️ 注意：这里说的是**用两根 GPIO 互补输出构成"伪差分"**（`DifferentialWirePair::set()` 也是同样思路：pinP 输出该位、pinM 输出其反），**不是单端单线**。这是 MCU 直连的关键点，也是 RP2040 PIO 方案用 `side_set` 一次设一对引脚的原因。

**【C｜存疑｜单点二手】ESP32 实现中的中文硬件注释**（`txpzyr/xy2_100`，见 §3.4）：
```cpp
//pin1-4 需要相对GND有1.2v
```
> **【推导】** 含义是：DB25 的 **pin 1–4**（= CLK−、SYNC−、X−、Y−，即各差分对的**负端**）**需要相对 GND 有约 1.2 V 的直流偏置**，单端驱动才能被振镜的差分接收器正确识别。RS-422 接收器的输入阈值是差分电压，若负端悬空或接地电位不当，接收器可能判不出有效电平。
> **本报告未能找到任何厂商文档确认"1.2 V"这个具体数值**，故该数值标记为**【C｜存疑、单点二手来源】**；但"负端需要直流偏置/参考"这一机理与 RS-422 接收器工作原理一致，可作为调试方向。

**【A｜一手】另一条硬性要求（`hyperchao0` README）**：
> "**Note:** To avoid the high impedance state of the differential line driver, the output of the line driver should be connected **pull-up or pull-down resistors**."
> → **差分驱动器输出必须加上拉/下拉电阻，避免三态（高阻）时输出悬浮被误判。**

**【B｜二手】`georgemihaila` 作者对低速直连的表态**：
> "Does this work at the standard rate of 2MHz? — **Most likely not, but an Arduino Nano seems to be able to drive a galvo just fine.**"

## 6. 扫描延迟与延时补偿（Laser Delay / Sky-Writing）

> 📎 本节的完整版（含 58 个独立来源、五厂商参数命名对照表、官方 6 步整定流程）见同目录 **《调研笔记-延迟量化数据》**。

### 6.1 四类延时的定义与缺陷现象

**【A｜一手】学术论文（IJMMM 2016）给出四类延时的标准定义**：
> "The proposed scanner delay includes four kinds of delays, which are **laser on-off delay, jump delay, mark delay and corner delay**."

| 延时 | 论文原文机理 | 过小的后果 | 过大的后果 |
|---|---|---|---|
| **Laser On/Off Delay**（开/关光延时 LOnD / LOffD） | "the appropriate laser on delay (LOnD) time and laser off delay (LOffD) time are meaningful to keep uniform laser power density" | 起点缺笔 / 终点未闭合 | 起点能量堆积、**终点产生爆点** |
| **Jump Delay**（跳转延时 JD） | "the jump delay works when the current … jump ends. … delay for a certain time after the jump ends" | 跳转未到位就开始标刻 → **路径紊乱（disordered path）**、"lack of material" | 效率下降、**材料过度堆积 / 不均匀** |
| **Mark Delay**（扫描延时 MarkD） | "The mark delay only works **before the command of jump**, laser will continue to work during the mark delay time"（**只在 Mark 后接 Jump 时生效**） | 坐标未到位即跳转 → **轮廓误差（contour error）** | 效率低（激光空烧） |
| **Corner / Polygon Delay**（拐角/多边形延时 PolyD） | 补偿拐角处两段矢量切换时振镜的加减速 | **轮廓误差** | 拐角处**材料过度堆积** |

来源：<https://www.ijmmm.org/vol6/402-EM0028.pdf>

> **【A｜一手｜重要更正】** 本报告逐页核对了该论文：**其正文不含任何具体 µs 数值**，只有机理与现象描述。（先前流传的"该论文有延时数值表"的说法不成立。）

**【A｜一手】「哪些参数只有单向风险」的双厂商互证（对 UI 校验设计极有价值）**：

| 参数 | RAYLASE 提供的症状图 | SAMLight Table 9 独立印证 | 结论 |
|---|---|---|---|
| `JumpDelay` | **仅** "Too Short" | 过大 "No problem, just increasing mark time" | **只需设下限** |
| `MarkDelay` | **仅** "Too Short" | 过大 "No problem" | **只需设下限** |
| `PolyDelay` | "Too Short" **+** "Too Long" | 过小→圆角；过大→burn-in | **需设上下限** |
| `LaserOnDelay` / `LaserOffDelay` | "Too Short" **+** "Too Long" | 双向均有缺陷 | **需设上下限** |

> 证据形态说明【A】：RAYLASE 官方症状说明全是 SVG 图，**图形文件名本身是不对称的**——Jump/Mark 只提供 "Too Short" 图，而 Poly/Laser 两者都有。来源：SP-ICE-3 手册 §7.3.2.1 / §7.3.3.1。

### 6.2 ★ 数字振镜的传递延迟（Transfer Delay）精确公式

**【A｜一手】RAYLASE SP-ICE-3 手册 §7.1.9 官方核心结论（原文）**：
> "you should set `LaserOnDelay` and `LaserOffDelay` to values that take the scanner's **total Positioning Delay** into account, i.e. **the sum of Transfer Delay and Tracking Error (a.k.a Lag)**."

| 量 | 公式 / 数值 |
|---|---|
| **Transfer Delay (TX 方向)** | `T_Int > 0`：**`TD_TX = T_K + T_C + T_Int`**，其中 **`T_K = 13 µs`**、**`T_C = 20 µs`**、`T_Int` = 插值时间；精度 **±2 µs** |
| | `T_Int = 0`：**`TD_TX = 14 µs`** |
| 代入官方推荐 `T_Int = 20 µs`（= 2× 帧周期） | **`TD_TX ≈ 53 µs`** |
| **Transfer Delay (RX 方向)** | **`TD_RX = 36 µs`**（常数） |
| 查询命令 | Enhanced Protocol `0x0556`(TX)、`0x0557`(TX+RX) |

来源：<https://software.raylase.de/rpi/RAYLASE/spice3/usersmanual/html/7a6d305c-a5d1-4dfb-a1d2-3afc1768b87f.htm>

**【推导】延迟链合计**：

```
控制器发出指令
   │  Transfer Delay TX ≈ 53 µs  (13 + 20 + 20)
   ▼
振镜头收到 20-bit 位置
   │  Tracking Error (Lag)  80 ~ 320 µs   ← 随型号/调谐/信号大小变化
   ▼
镜片真正到位
   ─────────────────────────────
   合计 ≈ 133 ~ 373 µs
```
**这与论文实测的开光 168–173 µs / 关光 450–460 µs 量级自洽。**

**【A｜一手】延迟的分辨率**：RAYLASE — **1/64 µs = 0.015625 µs**（"All timing parameter and property values will be automatically rounded down to the nearest 1/64 µs"）；SCANLAB RTC6 — **1/64 µs**（两家独立收敛到同一粒度）。

**【A｜一手】RAYLASE 官方**允许**负的开光/关光延时**（针对大型 CO₂ 等响应慢于振镜的激光器）；`TrackingError` 与 `LaserTriggerDelay` 是**两个独立参数**，分别取自振镜/激光器数据手册。

### 6.4 Sky-Writing（飞行打标 / 提前加速）

**【A｜一手】RAYLASE SP-ICE 3 手册 §9.5.1 完整定义（本次调研找到的最详细一手 Sky Writing 文档）**：

> **Fundamental Concept**：If we extend a MARK vector linearly by a suitable amount **before its original start point and after its original end point**, the scanner can use these extensions to **accelerate and decelerate while still outside the limits of the original vector**. The scanner then moves between the original start point and the original end point of each vector at **constant velocity**.

> **Delays between successive MARK vectors**：The currently defined `SKYWRITING_DECELERATION_DELAY` will take effect **after** the additional Sky Writing deceleration vector. **The current MARK_DELAY is ignored.** The currently defined `SKYWRITING_ACCELERATION_DELAY` will take effect **before** the additional Sky Writing acceleration vector. **The current JUMP_DELAY is ignored.**
> — "If the calculated Extension Distance is enough to allow the scanners to settle completely after the change of heading, **the delays may be reduced to 0**."

**Sky Writing 参数字典（原文摘要）**：

| 参数 | API / List Command | 含义 |
|---|---|---|
| Mode | `SkyWritingMode` / `SKYWRITING_MODE` | Disabled 时不生成任何 Sky Writing 矢量 |
| MinCoH | `SkyWritingSettings.MinCoH` / `SKYWRITING_MIN_COH` | 相邻 MARK 矢量转角**小于**此值时抑制 extension 与 jump 矢量；单位**弧度**；0/负/NaN → 总是插入；>π → 从不插入 |
| MergedExtensionsMaxCoH | `/ SKYWRITING_MERGED_EXTENSIONS_MAX_COH` | 启用"合并 extension"（0…π） |
| AccelerationDelay | `/ SKYWRITING_ACCELERATION_DELAY` | "Delay that is applied **after the jump to the extended start position, before acceleration**" |
| DecelerationDelay | `/ SKYWRITING_DECELERATION_DELAY` | "Delay that is applied **after deceleration at the end of a mark vector**" |
| ExtensionTime | `SKYWRITING_EXTENSION_TIME` | **Extension Distance = Extension Time × MarkSpeed**（原文公式） |
| LaserOnDelay | `/ SKYWRITING_LASERON_DELAY` | Sky Writing 专用开光延时，**替代** `ProcessVariables.LaserOnDelay` |
| LaserOffDelay | `/ SKYWRITING_LASEROFF_DELAY` | Sky Writing 专用关光延时，**替代** `ProcessVariables.LaserOffDelay` |

> 另有两条效率/质量注记（原文）：合并 extension 矢量"is performed at **MarkSpeed and without applying any mark delay or jump delay**"，且"**only considered if the JUMP vector between the two MARK vectors is shorter than double the length of the first MARK's extension vector**"（原文公式：`Length_JUMP < 2 · ExtensionTime₁ · MarkSpeed₁`）。

来源：<https://software.raylase.de/rpi/RAYLASE/spice3/usersmanual/html/4CF38177-3E6A-4E48-98D8-F5C30FBDAE14.htm>

**【推导】重要区别：Sky Writing ≠ 普通延时补偿**
- **普通延时补偿**：振镜按原路径走，只调整"激光开关时刻"与"等待时间" → 拐角仍是减速—停止—再加速。
- **Sky Writing**：**主动修改几何路径**（在原矢量两端各延长一段），让振镜在**额外矢量段内**完成加减速，从而在原始矢量段内保持**恒定速度** → 曝光均匀 + 拐角锐利。
- 因此 Sky Writing 会**改变机械运动轨迹**（标记区域不变），并且**需要 JUMP/MARK 之间插入额外矢量**。

**【未找到公开数据】**：Sky Writing 的 **Extension Distance 推荐数值**（手册只给公式）；Sky Writing 专用激光开关延时的**典型数值**。

### 6.6 更新率（100 kHz）与振镜带宽的关系

**【A｜一手】RAYLASE SP-ICE-3 官方 6 步整定流程（§7.4）**：
> 标定 → 编码器 → 旋转 → **用双向图案标定 TrackingError** → **在高速度下**整定 Jump/Mark/Poly（此时 LaserOn/Off 保持 0）→ **逐个速度档**整定 LaserOn/Off

> **【推导】由此流程可读出的工程含义**：**先让机械轨迹正确（TrackingError + Jump/Mark/Poly），再逐速度档标定激光时序。** 顺序反了会互相干扰。

**【推导】关于"多久发一个位置点"**：
- 帧周期 10 µs（100 kHz），而振镜跟踪延时 110–140 µs、阶跃响应 270–750 µs → **指令流比机械响应快 10–100 倍**。
- 振镜内部插值窗口默认 120 µs（≈8.3 kHz 等效）。**因此控制卡必须持续以不低于约 8 kHz 的速率发送位置帧**；若发送间隔大于插值时间设置，插值失效、轨迹出现台阶。
- 这与 §4.5 "时钟不能停" 是同一个要求：**即使位置不变也要重发**。

### 7.4 ★ 关于「~0.15 mrad 分辨率」—— **结论：这是把长期漂移误当分辨率**

**【A｜一手】证据链**：RAYLASE《SUPERSCAN IIE》官方手册 §3.7.1 通用规格表中**相邻的两行**分别是：

```
Resolution XY2-100 16-Bit                          12 μrad
Repeatability (RMS)                                < 2.0 μrad
Position noise (RMS)                               < 10 μrad
Max. Gain drift                                    15 ppm/K
Max. Offset drift                                  10 μrad/K
Long-term drift 8 h without water temperature      < 150 μrad      <-- ★ 150 µrad = 0.15 mrad
Long-term drift 8 h with water temperature control < 100 μrad
```

**`< 150 µrad` 就是 **0.15 mrad**，它是 8 小时长期漂移（无水冷）指标。**

| 说法 | 判定 |
|---|---|
| 「XY2-100 的分辨率约 0.15 mrad」 | **未能证实。** 一手数据给出的 16-bit 分辨率是 **11–12 µrad**，比 0.15 mrad **精细约 12–13 倍** |
| 「0.15 mrad」的真实出处 | 【C】极可能是把 RAYLASE 的 **8 小时长期漂移 <150 µrad（= 0.15 mrad）** 误读为"分辨率"。该数值与 12 µrad 的分辨率仅隔几行 |
| 其他厂商同量级漂移指标 | Sino-Galvo SG7110 与 JHC HC1510M 标 **8h 漂移 < 0.5 mrad**；RAYLASE SUPERSCAN III 标 **< 60 µrad = 0.06 mrad** |

**【A｜一手】反算**：若 16-bit LSB = 0.15 mrad，需光学全角范围 = 0.15 mrad × 65536 = **9.83 rad（≈563°）**——物理上不可能。0.15 mrad 在数值上更接近**一个 12-bit 系统**的 LSB。

**【A｜一手】LSB 换算验证（用一手数据核算，全部吻合）**：

| 位宽 | 步数 | 光学全角范围 | LSB 计算 | 官方值 | 吻合 |
|---|---|---|---|---|---|
| 16 bit | 65,536 | 2 × 0.393 rad = 786,000 µrad | **11.99 µrad** | RAYLASE **12 µrad** | ✅ |
| 16 bit | 65,536 | 2 × 0.36 rad = 720,000 µrad | **10.99 µrad** | SCANLAB **11 µrad** | ✅ |
| 18 bit | 262,144 | 720,000 µrad | **2.75 µrad** | SCANLAB **2.8 µrad** | ✅ |
| 20 bit | 1,048,576 | 720,000 µrad | **0.687 µrad** | SCANLAB **0.7 µrad** | ✅ |

> **通式（【推导】）**：`每 LSB 光学角 = 2 × θ_optical_max / 2^N`，`每 LSB 机械角 = 2 × θ_mech_max / 2^N`。
> **可靠基线：16 bit 覆盖 ±0.36…0.393 rad（光学）⇒ LSB ≈ 11–12 µrad ≈ 0.011–0.012 mrad。**
> **【推导】** 用 Sino-Galvo SG7220（机械 ±11° = 光学 ±0.384 rad）：0.768 rad / 65536 ≈ **11.7 µrad 光学 / 5.9 µrad 机械** —— 与 RAYLASE 的 6/12 µrad 一致。

**【A｜一手】SCANLAB 的关键限定 —— XY2-100 下就是 16 bit**：
> "18 bit: based on the full angle range (e.g. positioning resolution **2.8 µrad** for angle range ±0.36 rad), **resolutions better than 16 bit (11 µrad) only together with SL2-100 interface**"
> → **在 XY2-100 接口下，SCANLAB 振镜的可用定位分辨率就是 16 bit（≈11 µrad）；18/20-bit 需要换用 SL2-100。**
> （注：XY2-100**E** 协议本身支持 18-bit 帧，RAYLASE SS-III 也确实提供 18-bit 帧格式。这是**厂商实现选择**，不是协议能力上限。）

### 7.5 带宽（bandwidth）—— **厂商一律不给**

**【未找到公开数据｜重要】** 本次调研**未能找到任何振镜厂商以"带宽（Hz/kHz）"为单位给出的公开指标**。厂商一律给出**时域指标**：

| 厂商 / 型号 | 小信号阶跃（1% FS） | 大信号阶跃（10% FS） | 跟踪误差 |
|---|---|---|---|
| RAYLASE SS-III-10（ST） | 0.32 ms | 0.75 ms | 0.11–0.14 ms |
| Sino-Galvo SG7220-V1 | 275 µs | 750 µs | ≤138 µs |
| Sino-Galvo SG7220-Plus | 270 µs | 710 µs | ≤138 µs |
| SCANLAB hurrySCAN 20 | 0.80 ms | 2.50 ms | 0.35 ms |
| SCANLAB hurrySCAN 30 | 1.20 ms | 4.50 ms | 0.55 ms |
| SCANLAB intelliSCAN 14 | 0.45 ms | 3.0 ms | 0.15 ms |
| SCANLAB intelliSCAN 20 | 0.70 ms | 1.9 ms | 0.32 ms |
| SCANLAB intelliSCAN IV 14（SCAN ahead） | **0.25 ms** | 0.79 ms | **0 ms** |
| SCANLAB SCANcube 10 | 0.40 ms | 1.2 ms | 0.16 ms |
| Sino-Galvo SG7110 | 350 µs | 750 µs | ≤164 µs |

> → **小信号阶跃范围 0.19–0.80 ms；大信号阶跃 0.63–4.50 ms。**【A】
> SCANLAB intelliSCAN IV 14 的 "SCAN ahead" 实现**近似零跟踪误差**，说明现代方案已从"被动跟随"转向**利用模型与预知路径的主动预测控制**。【A】

**【推导】换算为等效带宽（一阶近似，仅作量级参考，非任何来源的指标）**：
- 跟踪误差 140 µs → 位置环等效带宽 ≈ 1/(2π×140 µs) ≈ **1.1 kHz**
- 小信号阶跃 275 µs（到 1% FS）→ ≈ **0.6 kHz**
- 大信号阶跃 750 µs（到 10% FS）→ ≈ **0.2 kHz**
> → **小信号带宽量级为亚 kHz 到 ~1 kHz，大信号更低。** 这与任务背景中假设的"1–10 kHz"**不一致**：1–10 kHz 更接近**小角度/谐振频率**量级，而非"到指定精度的整定带宽"。
> **【C】** 上述换算来自本报告的一阶近似，**不是厂商指标**。需要真实 −3 dB 带宽必须向厂商索取频响曲线 —— **本报告未找到公开数据**。

### 7.6 典型标刻速度与 F-Theta 镜头

**【A｜一手】** 厂商指标均在**指定 F-Theta 焦距**下测得：

| 厂商 | 打标速度测试条件 |
|---|---|
| SCANLAB | "Marking speed (**f = 160 mm**)" |
| Sino-Galvo | "With F-theta objective, **F=160mm**, marking **2mm height** single character" |
| Sintec | "with F-Theta objective, **f=160mm**"；写入速度用 **1 mm 高**单线字符 |
| RAYLASE III-10 | f = 163 mm、视场 120 × 120 mm |

> → **跨厂商比较打标速度时，必须在同样的 f = 160 mm、同样的字符高度下比较**，否则数值不可比。

**【推导】速度与分辨率随焦距的换算**：
- 工件表面线速度 `v = f × ω`（小角近似）。
- 工作面每 LSB 尺寸 = `f × 每 LSB 角`。
  例：SG7220（机械 ±11°，光学 ±0.384 rad）配 f = 160 mm → 每 LSB 光学 11.7 µrad × 160 mm ≈ **1.87 µm**；18-bit 则约 **0.47 µm**。
- **换用更长焦距镜头 ⇒ 同样角速度得到更高线速度，但同样位宽的工作面分辨率变粗。**

**【推导】精度受限因素（综合分析）**：
1. **量化误差**：16 bit → ~1.9 µm（f = 160 mm）；18 bit → ~0.47 µm。**需要亚 µm 精度时 16 bit 不够。**
2. **零点漂移 15 µrad/°C → 在 f = 160 mm 上约 2.4 µm/°C**；环境 ±5 °C 波动即 ~12 µm。
3. **长期漂移 < 0.15 mrad → 在 f = 160 mm 上约 24 µm/8 小时。**
4. **重复定位精度 < 8 µrad → 约 1.3 µm（RMS）。**
5. **F-Theta 镜头畸变**：厂商只给"线性度 99.9%"这一个标量 —— **未找到畸变曲线（未找到公开数据）**。0.1% 的非线性随视场放大，是长焦距大视场下的主要误差源。
6. **跟踪误差（动态）**：拐角变圆、圆弧失真 —— 速度相关误差，与上述静态误差独立。
7. **镜片惯量/轴承摩擦**：厂商只以"阶跃响应/加速度时间"间接体现，**未给出惯量或摩擦力矩数值（未找到公开数据）**。

### 7.7 机械角 vs 光学角（易混淆点，务必区分）

**【A｜一手】各厂商的标注方式不同**：

| 厂商 | 原文标注 | 实际含义 |
|---|---|---|
| RAYLASE | "Typical deflection (optical) = ±0.393 rad"；"Remark: **All angles optical**" | 光学角 |
| SCANLAB | "**±0.35 rad (optical)**" | 光学角 |
| Sino-Galvo / JHC | "**Mechanical** Scan Angle ±11°" | **机械角** |
| Cambridge Technology | "all angles in **mechanical** degrees" | 机械角 |
| Sintec | "all angles in **optical** degrees" | 光学角 |

**【推导】换算**：±0.393 rad 光学 = ±22.5° 光学 = **±11.25° 机械** ≈ Sino-Galvo 的 ±11° 机械。
→ **两家 10 mm 口径产品的机械扫描角量级一致（约 ±11°），光学角约 ±22°。**
→ **镜面反射使光学角 = 2 × 机械角。**

> **⚠️ 工程提醒**：写规格时若把"±11° 机械"当成"±11° 光学"，会低估实际视场 2 倍，或在做角度→位置码换算时引入 2 倍误差。**F-Theta 镜头的设计焦距也是按光学角定义的。**

## 11. 给实现者的速查清单

### 11.1 发送一帧的最小正确伪代码（综合 §1–§4 多来源验证）

```text
# 20 位帧，MSB 先发；数据在 CLK 上升沿变化，振镜在 CLK 下降沿采样
bits = [C2, C1, C0] + [(D15..D0) 的 16 位]        # 16 bit 模式: C2C1C0 = 0,0,1
P = XOR(C2, C1, C0, D15, ..., D0)                 # 偶校验，统计 19 位（不要漏掉 C0！）
bits += [P]

SYNC = 1                       # 与第 1 位同沿上升
for i, b in enumerate(bits):   # i = 0..19
    if i == 19:                # 第 20 位 = 校验位
        SYNC = 0               # SYNC 拉低
    DATA = b
    CLK = 1                    # 上升沿：数据变化
    # 保持 >= tDS (50 ns)
    CLK = 0                    # 下降沿：振镜采样
    # 保持 >= tDH (100 ns)
# 帧周期目标 10 µs（100 kHz）；空闲时也必须继续发帧（重复当前位置），不可停时钟
```

### 11.2 检查表

| # | 检查项 | 正确做法 | 见 |
|---|---|---|---|
| 1 | 数据变化沿 / 采样沿 | 上升沿变化、下降沿采样；MCU 上用 SPI **CPOL=1/CPHA=0**（或 PIO/定时器显式控制） | §4.1 |
| 2 | SYNC 宽度 | 高 **19** 位，**仅第 20 位（校验位）为低** | §4.2 |
| 3 | 奇偶 | `P = XOR(C2,C1,C0,D15..D0)`，**含 C0**（漏掉 C0 会得到相反的奇校验） | §1.3 |
| 4 | 帧头 | 16 bit 位置帧 = `001`；18 bit = 首位 `1` + **奇**校验；命令帧 = `111` | §1.1、§1.4 |
| 5 | 空闲行为 | **持续发送时钟 + SYNC 帧**（重复当前位置）；时钟停止会被振镜判为故障并**关闭输出级** | §4.5 |
| 6 | FIFO 断流 | 必须有"复用上一帧"的兜底（PIO `tx_empty` / 双通道包指针） | §3.3、§3.7 |
| 7 | 上电默认值 | 位置码默认 **0x8000（中点）**，不是 0 | §2.1 |
| 8 | 坐标映射 | `code = 0x8000 + signed_pos`（offset binary）；**注意 X/Y 通道在不同厂商间可能互换** | §2.1、§4.8 |
| 9 | 电平 | **RS-422** 差分：驱动 AM26LS31 / SN75174 / UA9638，接收 AM26LV32 / UA9637 / MAX3096；驱动器输出加上拉/下拉防三态 | §5.1、§5.2 |
| 10 | 短距直连 | 3.3 V **互补双 GPIO 伪差分**（不是单端单线）可用于短线；负端需要直流参考 | §5.2 |
| 11 | 端接 | 两个真实开源设计**都不加**终端电阻（2 Mbit/s 点对点短距）；官方**无规定值** → **以实测波形为准** | §4.8 |
| 12 | 延时参数量级 | 开光 ≈170 µs / 关光 ≈450 µs / 跳转 ≈200 µs / 扫描 ≈150 µs / 拐角 100–160 µs（全部为 10 µs 整数倍） | §6.5 |
| 13 | 延时方向性 | Jump/Mark **只需下限**；Poly/LaserOn/LaserOff **需上下限** | §6.1 |
| 14 | 速度 vs 精度 | 拐角变圆是**加速度不足**，调延时无用；应降速或启用 Sky Writing | §6.4、§7.5 |
| 15 | 16 vs 18 bit | 16 bit ≈ **6 µrad 机械 / 12 µrad 光学**；18 bit ≈ **1.5 / 3 µrad** | §7.1、§7.4 |
| 16 | 角度定义 | **务必区分机械角与光学角（差 2 倍）**；镜头焦距按光学角定义 | §7.7 |
| 17 | 协议固有缺陷 | 命令帧与 18 bit 帧无法区分 → 关键命令需**回读确认** | §4.4 |
| 18 | 位置帧发送间隔 | 必须 **≤ 振镜插值时间设置**（默认 120 µs ≈ 8.3 kHz），否则轨迹出现台阶 | §4.6 |
